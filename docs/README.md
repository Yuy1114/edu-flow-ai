## 当前架构边界

```text
核心思路: 绝对周占位 → 已完成任务释放资源 → 按周课表签名派生动态模板

时间坐标: 每天 11 个 45 分钟原子小节（上午1-4、下午5-8、晚上9-11）
          晚间是学校作息 19:10-21:35 的三节大块
          自动排课默认工作日 1-8；9-11 和周末保留人工使用
输入接口: Java 仅传 allocation_task_id
决策粒度: 每个 teaching_task 按 pattern 在 (week, day, period, classroom) 上占位
求解方式: 硬约束全枚举 + 贪心放置 + 1~2 任务局部重排；失败只标待人工，不证明无解
落库:     schedule_template / _week / _fragment / _fragment_slot 及教师、班级多值关系表
输出:     模板落库 → 前端按周展开 → 确认物化为 course_assignment → 四视角 Excel 导出

模型:     第一阶段 rules-only；排序模型以后只排序合法候选，旧时间轴模型会被拒绝并降级
教师画像: 采集与聚合已就位，但目前不进入排课引擎（见 architecture/19 第 6.3 节）
```

正式链路：`allocation_task_id` → Java `V35TemplateGenerationService` → Python 持久化 HTTP 作业 →
`scheduler.run_pipeline` → pattern 构建 → 绝对周排布 → 动态模板草案 → DB 原子事务入库 →
前端精确周次人工编辑/重审计 → 确认物化为 `course_assignment` → 多条件正式课表与课时终审。

Python 侧代码布局见 `backend/python/README.md`（scheduler = 排课引擎，ingest = 导入与训练闭环）。

## 归档原则

`docs/archive/` 只进不出，保存 V1 GA → V2 双通道/Beam → V2.5 候选池 → V3 CP-SAT →
V3.5 动态周模板五代方案的设计与取舍过程。这条演进线本身是论文第 2 章的一手材料，
所以归档而不是删除。

`docs/archive/` 与 `docs/feedback/` 都纳入版本管理。`.gitignore` 曾排除这两条路径，于是
归档只发生在本地：`d0e65c2` 从索引移走 26 份归档文档的同一次提交里加上了 `docs/archive`
忽略，`docs/feedback` 也在 06-15 被一并忽略。2026-10-05 移除这两条排除，补齐 26 份归档
与 2 份反馈文档，此后不再忽略。

判断标准：**主题本身已经退役**（方案被删除、被取代）就归档；只是内容需要更新的留在原处
并标注状态。凡是索引里的路径都应真实存在——本索引在 2026-09-06 之前列有 14 个
已在 `c3e8a3a` 移入 `archive/` 的文件，其中若干还标着「✅ 仍适用」。新增或移动文档时
请同步本文件。
