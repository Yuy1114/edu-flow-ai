# 答辩 PPT 大纲

> 更新时间：2026-05-26
> 目标：先确定答辩 PPT 的故事线和页面结构，后续再补实验结果、截图和视觉设计。本文档不是最终 PPT，而是制作 PPT 的内容脚本。

## 总体讲述策略

答辩不要从代码细节开始讲，而要从问题出发：

```text
排课难在哪里
  ↓
为什么不能只靠规则或大模型
  ↓
为什么采用教师画像 + LightGBM + GA
  ↓
系统链路如何设计
  ↓
训练样本如何构建
  ↓
实验如何证明有效
```

一句话主线：

```text
GBM 学片段质量，GA 组完整课表，教师画像提供个性化偏好，人工反馈让模型持续进化。
```

## 推荐页数

建议 12~15 页，不要太长。

如果答辩时间短，用 12 页；如果时间充足，用 15 页。

## 第 1 页：标题页

标题建议：

```text
基于学习引导候选空间压缩与遗传搜索优化的高校智能排课系统设计与实现
```

内容：

- 姓名。
- 专业 / 班级。
- 指导老师。
- 日期。

视觉建议：

- 背景可以用简洁课表网格元素。
- 不要堆太多技术关键词。

## 第 2 页：研究背景与问题

要讲的问题：

- 高校排课涉及教师、班级、教室、时间片等多类资源。
- 硬约束多，人工排课容易冲突。
- 教师偏好、班级负载、课程分布等软约束难以完全靠规则表达。
- 人工调整过程中的经验没有被沉淀为可训练数据。

页面结构：

| 问题 | 表现 |
|---|---|
| 资源冲突 | 教师 / 班级 / 教室时间冲突 |
| 偏好复杂 | 教师时间偏好、负载偏好 |
| 调整成本高 | 生成后还需要大量人工修改 |
| 经验难沉淀 | 调整原因没有进入模型训练 |

## 第 3 页：研究目标

核心目标：

```text
构建一套可解释、可优化、可反馈学习的智能排课系统。
```

拆成 4 点：

1. 保证排课方案满足硬约束。
2. 尽量满足教师画像中的个性化偏好。
3. 使用模型学习真实课表和人工反馈中的隐性偏好。
4. 通过 GA 完成完整课表的全局组合优化。

## 第 4 页：总体技术路线

建议放一张主链路图：

```text
基础数据
  ↓
教师画像
  ↓
片段级训练样本
  ↓
学习模型生成并预评分候选集
  ↓
GA 全局组合优化
  ↓
课表方案输出
  ↓
人工反馈
  ↓
模型训练闭环
```

讲述重点：

- 不是让 LLM 直接生成课表。
- 规则保证合法性。
- 模型学习局部偏好，用于压缩候选空间。
- GA 负责在候选集里组合完整方案。

## 第 5 页：系统架构设计

内容：

- 前端：生成配置、方案展示、教师画像录入。
- Java 后端：业务编排、教师画像处理、方案入库、反馈事件。
- Python 服务：数据加载、候选池构建、Placement Scorer、GA 搜索。
- 数据层：教学任务、教师画像、课表方案、反馈样本。

建议图：

```text
前端 → Java后端 → Python排课服务 → schemes.jsonl → Java入库 → 前端展示
```

## 第 6 页：教师画像设计

重点：教师画像是创新点之一。

页面内容：

| 画像类型 | 示例 | 作用 |
|---|---|---|
| 时间画像 | 避免早八、周三下午不可排 | 过滤 / penalty |
| 负载画像 | 每天最多几节、偏好集中排课 | GA penalty |
| 空间画像 | 偏好楼栋、教室类型 | 教室评分 |
| 行为画像 | 历史调课次数、常见原因 | 模型特征 |

讲述口径：

```text
教师画像不是简单文本备注，而是转成结构化特征，进入候选过滤、规则惩罚和模型评分。
```

## 第 7 页：训练样本构建

重点回答老师关心的“样本从哪来”。

数据来源：

| 来源 | 用途 |
|---|---|
| 学校真实课表 | 高可信正样本 |
| AI 生成满意课表 | 扩充正样本 |
| 人工调整记录 | 强正 / 强负样本 |
| 冲突检测结果 | 强负样本 |
| 规则 sample.csv | 冷启动弱监督样本 |

讲述口径：

```text
现有 sample.csv 不能作为主要训练数据，只能作为冷启动。真正训练数据来自真实课表、人工认可的 AI 课表和教务调整反馈。
```

## 第 8 页：样本单位与标签设计

页面重点：片段级样本。

样本定义：

```text
sample = teaching_task + teacher + class_group + time_slot + classroom + context
```

三层样本：

| 层级 | 用途 |
|---|---|
| 片段级 | 主训练单位 |
| 调整对级 | 学习人工偏好 |
| 方案级 | 最终业务评估 |

标签例子：

| 样本来源 | label |
|---|---:|
| 学校真实课表片段 | 1.0 |
| 人工调整后片段 | 1.0 |
| 人工调整前片段 | 0.0 |
| 冲突片段 | 0.0 |

## 第 9 页：LightGBM 选型说明

重点回答：为什么选 GBM？

页面内容：

| 方法 | 特点 | 本项目定位 |
|---|---|---|
| 纯规则 | 可解释，但不能学习隐性偏好 | 基线与硬约束 |
| RandomForest | 稳定，适合对照 | 消融对照组 |
| LightGBM | 表格数据友好、训练快、能拟合难样本 | 主评分器 |
| 深度学习 | 数据需求高、解释成本高 | 暂不作为主方案 |

答辩口径：

```text
LightGBM 不替代 GA，只对候选片段评分；RandomForest 会作为对照组进入消融实验。
```

## 第 10 页：GA 编码与适应度函数

页面内容：

染色体：

```text
Chromosome = [TaskGene_1, TaskGene_2, ..., TaskGene_n]
```

基因：

```text
TaskGene = { task_id, template_set_id, slot_id, classroom_id }
```

适应度函数：

```text
Fitness = HardPenalty × W_h
        + SoftPenalty × W_s
        + TemplatePenalty × W_t
        - ModelQuality × W_m
```

讲述重点：

- 硬约束权重最高。
- 软约束影响方案质量。
- 模型质量分引导 GA 搜索。

## 第 11 页：评分归一化与模型接入

重点讲 sigmoid。

公式：

```text
raw_i = model_i - λ × penalty_i
q_i = sigmoid(raw_i / T)
```

作用：

- 把模型分和规则惩罚统一到 `[0,1]`。
- 避免极端分数主导 GA。
- 方便不同模型公平对比。

接入位置：

- 初始化候选排序。
- repair 候选替换排序。
- fitness 模型质量项。

## 第 12 页：消融实验设计

核心实验组：

| 组别 | 方法 | 目的 |
|---|---|---|
| A | 规则 + GA | 基线 |
| B | GA + RandomForest | 对比传统模型 |
| C | GA + LightGBM | 验证主方案 |
| D | GA + LightGBM + 教师画像增强 | 验证画像贡献 |

指标：

- 硬约束冲突数。
- 教师偏好满足率。
- 人工调整次数。
- 平均 fitness。
- 生成耗时。
- 方案采纳率。

## 第 14 页：总结与创新点

创新点：

1. 教师画像驱动的个性化排课约束与特征设计。
2. LightGBM 局部评分 + GA 全局优化的混合排课方法。
3. 真实课表、AI 满意课表和人工反馈结合的训练数据链路。
4. 通过消融实验验证模型和教师画像贡献。

总结句：

```text
本项目通过“规则保合法、模型学偏好、GA做组合、反馈促迭代”的方式，构建了一套可解释、可扩展的智能排课系统。
```

## 第 15 页：不足与展望

不足：

- 真实课表和人工反馈样本仍需继续积累。
- 教师画像解析质量会影响排课效果。
- 模型当前主要做局部评分，不能完全代表整张课表质量。

展望：

- 引入更多真实学期课表。
- 增强 pairwise ranking 偏好学习。
- 优化 GA 参数自适应调整。
- 完善反馈标注和模型重训机制。
