# 模型训练数据链路设计

> ⚠️ **V3 更新 (2026-06-02)**: 本文档描述的是 V2 的"片段级评分器训练链路"（GA 评分模型）。V3 已切换为 **Placement Model**（多分类）训练链路，核心区别：
> - V2: 样本单位 = 片段 `(task, slot, room) → score`，标签来自 GA 方案/人工反馈
> - V3: 样本单位 = 任务 `task → resource_key`（13 特征 → 3953 类），标签来自真实课表
> - V3 训练数据直接从清洗后课表提取（`build_v3_placement_direct_training_data.py`），不经过 GA 自举
>
> 本文档的"片段级→调整对级→方案级"三层样本体系方法论仍有参考价值，但当前训练链路实现以 V3 为准。详见 [17-V3-CP-SAT排课架构设计](./17-V3-CP-SAT排课架构设计.md)。
>
## 1. 设计背景

当前系统已经具备 GA + LightGBM 的排课生成链路，但模型训练数据仍然偏弱。现有规则生成的 `sample.csv` 主要来自人工规则构造，只能帮助模型学习容量、时间段、基础冲突等显式规则，不能代表学校真实排课习惯，也难以支撑有效的模型训练和消融实验。

因此，后续训练链路需要从“规则伪样本”转向“真实课表 + 人工认可生成课表 + 反馈行为”的混合样本体系。

核心目标：

```text
学校真实课表
  + 人工认可的 AI 生成课表
  + 教务调整反馈
  → 清洗与标准化
  → 候选片段样本
  → 特征构造
  → 标签与权重
  → 模型训练
  → 消融实验
```

## 2. 样本单位

本项目采用“三层样本单位”设计：片段级样本作为主训练单位，调整对样本作为偏好增强，方案级样本作为最终业务评估单位。

| 层级 | 样本单位 | 主要用途 | 当前优先级 |
|---|---|---|---|
| 片段级 | 一条具体课程安排 | 训练 LightGBM / RandomForest / XGBoost 局部评分器 | 最高 |
| 调整对级 | 调整前片段 vs 调整后片段 | 学习人工调整中的相对偏好 | 中 |
| 方案级 | 一整张课表 | 评估最终排课质量，不作为主模型直接训练单位 | 低 |

### 2.1 片段级样本

模型不直接学习“一整张课表是否好”，而是学习“一个候选排课片段是否合适”。

一个片段级训练样本定义为：

```text
sample = f(teaching_task, teacher, class_group, time_slot, classroom, context)
```

对应业务含义：

```text
某个教学任务，由某位教师，在某个时间片，安排到某个教室，在当前课表上下文中是否合理。
```

片段级样本是主训练单位，原因是：

- 一张真实课表可以拆分成多条片段样本，缓解真实课表数量不足的问题。
- 单个候选片段更容易构造成结构化特征，适合 LightGBM、RandomForest、XGBoost 等表格模型。
- 模型输出的片段质量分可以直接接入 GA 的初始化、候选排序、repair 和 fitness 计算。
- 后续消融实验可以在同一批片段样本上替换不同评分器，而不用重写 GA。

### 2.2 上下文特征

片段样本不能只包含 `teacher + time_slot + classroom`，否则会忽略当前课表状态。一个片段是否合理，往往取决于它放入当前方案后的局部上下文。

因此，片段样本中必须包含 `context`：

| 上下文特征 | 说明 |
|---|---|
| teacher_day_load | 教师当天已有课时 |
| teacher_week_load | 教师本周已有课时 |
| class_day_load | 班级当天课程密度 |
| room_day_load | 教室当天使用情况 |
| same_day_continuous_count | 是否导致连续授课过多 |
| teacher_preference_hit | 是否命中教师画像偏好 |
| conflict_risk | 放入当前方案后的冲突风险 |

也就是说，模型学习的不是孤立片段，而是：

```text
候选排课片段 + 当前局部课表状态 → 局部质量分
```

### 2.3 调整对样本

人工调整行为可以进一步构造为调整对样本。例如教务把一个片段从 A 位置移动到 B 位置，可以得到：

```text
before_assignment < after_assignment
```

含义是：

```text
调整后的片段质量高于调整前片段。
```

调整对样本适合用于后续扩展 pairwise ranking 或偏好学习。当前阶段可以先记录数据结构，不必立即实现复杂排序模型。

### 2.4 方案级样本

方案级样本表示一整张课表，包括：

```text
scheme_score, conflict_count, teacher_preference_satisfaction, manual_adjustment_count, fitness, accepted_or_not
```

方案级数据主要用于最终业务评估，不建议作为主模型直接训练单位。原因是完整课表维度高、样本数量少、标签难定义，且完整组合优化本来就是 GA 的职责。

最终分工为：

```text
GBM / RF / XGBoost 学习局部片段质量
GA 负责完整课表组合优化
方案级指标负责验证最终排课效果
```

## 3. 数据来源

### 3.1 学校真实课表

学校提供的历史课表、已执行课表、人工确认课表，是最高可信度的数据来源。

用途：

- 作为高可信正样本。
- 学习学校真实排课习惯。
- 学习课程、教师、班级、教室、时间之间的常见匹配关系。

需要采集字段：

| 字段 | 说明 |
|---|---|
| course_name / teaching_task_id | 课程或教学任务 |
| teacher_name / teacher_id | 授课教师 |
| class_group_name / class_group_id | 班级或合班信息 |
| classroom_name / classroom_id | 教室 |
| week_number / week_mask | 周次 |
| day_of_week | 星期 |
| period_index | 节次 |
| student_count | 学生人数 |
| room_capacity | 教室容量 |
| room_type | 教室类型 |

### 3.2 AI 生成满意课表

在真实数据不足时，可以让 AI 或系统基于同一批教学任务和约束生成多套课表，再由人工筛选“看着满意”的方案。

用途：

- 扩充正样本。
- 补足真实课表数量不足的问题。
- 为早期训练提供更接近真实业务的弱监督样本。

注意：

- 未经人工筛选的 AI 课表不能直接作为正样本。
- 被人工认为满意的 AI 课表可作为中高可信样本。
- 被人工认为不满意的 AI 课表可以作为负样本或待分析样本。

### 3.3 教务反馈行为

系统上线或测试过程中产生的人工调整，是训练模型的重要反馈来源。

典型事件：

| 事件 | 样本含义 |
|---|---|
| 方案被确认 | 方案中的片段可作为正样本 |
| 片段被移动 | 移动前为负样本，移动后为正样本 |
| 片段被删除 | 原片段可作为负样本 |
| 片段被标记好 / 坏 | 直接形成标注样本 |
| 冲突检测失败 | 冲突片段作为强负样本 |

### 3.4 规则生成样本

当前 `sample.csv` 属于规则冷启动样本。

定位：

- 可以用于冷启动。
- 可以用于模型预训练。
- 可以作为无真实数据时的兜底样本。
- 不能作为主要训练数据。

原因：

- 标签来自规则，不来自真实排课行为。
- 容易让模型只学习已有规则，而不是学习隐性偏好。
- 无法证明模型优于规则系统。

## 4. 数据清洗

原始课表通常存在格式不统一、命名不一致、字段缺失等问题，需要先清洗。

### 4.1 字段标准化

| 原始问题 | 处理方式 |
|---|---|
| 星期格式不统一 | 统一为 `day_of_week = 1~7` |
| 节次格式不统一 | 统一为 `period_index = 1~5` |
| 周次格式不统一 | 转换为 `week_number` 或 `week_mask` |
| 教师名称不一致 | 建立教师名称到 `teacher_id` 的映射 |
| 教室名称不一致 | 建立教室名称到 `classroom_id` 的映射 |
| 班级名称不一致 | 建立班级名称到 `class_group_id` 的映射 |

### 4.2 异常数据处理

| 异常类型 | 处理方式 |
|---|---|
| 缺少教师 | 不进入训练集 |
| 缺少时间片 | 不进入训练集 |
| 缺少教室 | 可保留为无教室样本，也可剔除 |
| 教室容量小于班级人数 | 标记为硬非法，不作为正样本 |
| 教师命中硬不可排 | 标记为硬非法，不作为正样本 |
| 同一教师同一时间多课 | 标记冲突，作为负样本或剔除 |
| 同一班级同一时间多课 | 标记冲突，作为负样本或剔除 |
| 同一教室同一时间多课 | 标记冲突，作为负样本或剔除 |

### 4.3 AI 生成课表筛选

AI 生成课表必须经过人工筛选后才能进入训练集。

建议分三类：

| 类型 | 处理方式 |
|---|---|
| 人工满意 | 转为正样本 |
| 人工不满意 | 转为负样本或记录原因 |
| 未评价 | 暂不进入训练集 |

## 5. 样本构造

### 5.1 正样本构造

正样本来源：

| 来源 | label | 说明 |
|---|---:|---|
| 学校真实课表片段 | 1.0 | 高可信正样本 |
| 人工确认系统方案 | 1.0 | 普通正样本 |
| 人工认可 AI 课表片段 | 1.0 | 扩充正样本 |
| 人工调整后的片段 | 1.0 | 强正样本 |

### 5.2 负样本构造

只靠真实课表会导致样本几乎全是正样本，因此必须构造负样本。

负样本来源：

| 来源 | label | 说明 |
|---|---:|---|
| 人工调整前的片段 | 0.0 | 被教务替换的位置 |
| 人工拒绝的 AI 片段 | 0.0 | 人工认为不满意 |
| 冲突片段 | 0.0 | 硬冲突或明显不可用 |
| 随机替换时间 / 教室后的候选 | 0.0 | 合成负样本 |
| 违反教师画像偏好的候选 | 0.0~0.4 | 软负样本 |

合成负样本要注意：

- 不要只生成特别离谱的负样本，否则模型学不到细粒度排序。
- 应该包含一部分“合法但不优”的候选，例如时间不太理想、教室稍远、教师当天负载偏高。
- 硬冲突负样本可以保留少量用于训练，但不能让模型替代规则判断硬约束。

## 7. 标签与权重

| 样本来源 | label | sample_weight | 说明 |
|---|---:|---:|---|
| 学校真实课表片段 | 1.0 | 1.2 | 高可信正样本 |
| 人工调整后的片段 | 1.0 | 1.4 | 强正样本 |
| 人工认可 AI 课表片段 | 1.0 | 0.8~1.0 | 扩充正样本 |
| 人工确认系统方案片段 | 1.0 | 1.0 | 普通正样本 |
| 人工调整前的片段 | 0.0 | 1.2 | 负样本 |
| 人工不满意 AI 片段 | 0.0 | 0.8~1.2 | 负样本 |
| 冲突片段 | 0.0 | 1.3 | 强负样本 |
| 规则冷启动样本 | 0.0~1.0 | 0.3~0.5 | 弱监督样本 |

权重设计原则：

```text
人工明确反馈 > 学校真实课表 > 人工认可 AI 课表 > 规则生成样本
```

## 8. 评分归一化

模型训练和 GA 调用时，不同评分来源的数值范围可能不同。例如模型原始分、规则惩罚分、教师画像惩罚分可能分别处在不同尺度。为了避免某一类分数项过度主导 GA 搜索过程，需要把综合评分统一映射到 `[0, 1]` 区间。

本项目采用 sigmoid 函数进行评分归一化：

```text
sigmoid(x) = 1 / (1 + e^(-x))
```

候选片段的综合原始评分定义为：

```text
raw_i = model_i - λ × penalty_i
```

归一化后的片段质量分为：

```text
q_i = sigmoid(raw_i / T)
```

其中：

| 符号 | 含义 |
|---|---|
| `model_i` | 模型对第 `i` 个候选片段的原始评分 |
| `penalty_i` | 规则惩罚、教师画像惩罚、冲突风险惩罚等软惩罚 |
| `λ` | 惩罚项权重 |
| `T` | 温度系数，用于避免 sigmoid 过早饱和 |
| `q_i` | 映射到 `[0, 1]` 的候选片段质量分 |

如果某一阶段只有惩罚分，没有模型分，也可以使用：

```text
q_i = sigmoid(-penalty_i / T)
```

评分解释：

- `q_i` 越接近 1，表示候选片段越适合被选入最终课表。
- `q_i` 越接近 0，表示候选片段质量越低。
- `T` 越大，分数变化越平滑；`T` 越小，分数越容易接近 0 或 1。

sigmoid 归一化的作用：

- 统一模型分、规则分和画像惩罚的尺度。
- 压缩极端值，避免异常大分数直接主导 GA。
- 让不同模型输出都能转换成同一套候选质量分。
- 方便 LightGBM、RandomForest、XGBoost 和纯规则评分在消融实验中公平比较。

## 9. 数据集划分

不建议随机按片段打散划分训练集和测试集，因为同一张课表中的片段高度相关。

推荐按排课任务、学期或数据来源划分：

```text
训练集：历史课表 A/B/C + 部分人工认可 AI 课表
验证集：历史课表 D
测试集：历史课表 E 或最近一次真实排课任务
```

这样可以避免数据泄漏，让测试结果更接近真实泛化能力。

## 10. 模型训练流程

```text
真实课表 / AI 满意课表 / 反馈事件
  ↓
字段标准化与 ID 映射
  ↓
异常数据清洗
  ↓
片段样本构造
  ↓
负样本生成
  ↓
特征构造
  ↓
标签与权重生成
  ↓
训练 / 验证 / 测试集划分
  ↓
训练 LightGBM、RandomForest、XGBoost 等模型
  ↓
离线评估
  ↓
接入 GA 做端到端排课评估
```

## 11. 评估指标

### 11.1 模型指标

| 指标 | 说明 |
|---|---|
| AUC | 区分好坏候选的能力 |
| LogLoss | 概率预测质量 |
| Precision@K | 排名前 K 候选中正样本比例 |
| NDCG@K | 排序质量 |

### 11.2 排课业务指标

| 指标 | 说明 |
|---|---|
| 硬约束冲突数 | 教师、班级、教室冲突数量 |
| 教师偏好满足率 | 满足画像偏好的比例 |
| 人工调整次数 | 教务需要手动修改的片段数 |
| 平均 fitness | GA 输出方案质量 |
| 方案生成耗时 | 一次生成所需时间 |
| 方案采纳率 | 方案被人工接受的比例 |

模型指标用于判断评分器是否学到了片段质量，业务指标用于判断模型接入 GA 后是否真的改善排课结果。

## 12. 消融实验衔接

训练链路打通后，消融实验使用同一批训练数据、同一套特征、同一套评估指标，只替换模型或特征组合。

建议实验组：

| 组别 | 方法 | 目的 |
|---|---|---|
| A | 规则 + GA | 无机器学习基线 |
| B | GA + RandomForest | 对比传统集成学习 |
| C | GA + LightGBM | 验证 GBM 主方案 |
| D | GA + XGBoost | 可选增强对比 |
| E | GA + LightGBM + 教师画像增强 | 验证教师画像贡献 |

最终要证明的不是“LightGBM 永远最强”，而是：

```text
在学校课表结构化数据和教师画像特征场景下，LightGBM 能在候选排序质量、教师偏好满足率和生成耗时之间取得更好的平衡。
```

## 13. 当前落地优先级

1. 收集学校真实课表样例。
2. 定义真实课表导入字段模板。
3. 设计 AI 生成课表的人工筛选标准。
4. 把真实课表和 AI 满意课表统一转成片段样本。
5. 建立特征 schema 和标签规则。
6. 再开始训练 LightGBM / RandomForest / XGBoost。
7. 最后做模型消融实验。
