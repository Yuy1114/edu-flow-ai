# GA 编码与适应度函数设计

> 更新时间：2026-05-29
> 目标：从论文与答辩角度说明遗传算法在本项目中的编码方式、约束建模、适应度函数和遗传操作，回答“GA 到底在优化什么”。

## 1. 设计定位

本项目中的遗传算法不负责理解自然语言，也不直接学习教师偏好。GA 的核心职责是：

```text
在满足硬约束的前提下，从大量候选排课片段中搜索一张整体质量较高的完整课表。
```

LightGBM / RandomForest 等模型负责对局部候选片段打分，GA 负责把这些片段组合成完整方案。

两者分工如下：

| 模块 | 职责 |
|---|---|
| 规则系统 | 判断硬约束是否合法，计算基础 penalty |
| 教师画像 | 提供硬不可排、软偏好和画像 penalty |
| 机器学习模型 | 评估候选片段局部质量 |
| GA | 进行完整课表的全局组合搜索 |

## 2. 染色体编码

### 2.1 染色体含义

一个染色体表示一张完整候选课表：

```text
Chromosome = [TaskGene_1, TaskGene_2, ..., TaskGene_n]
```

其中，每个 `TaskGene` 对应一个教学任务的排课安排。

### 2.2 基因编码

一个基因表示一个教学任务的排课方案：

```text
TaskGene = {
  task_id,
  template_set_id,
  assignments: [
    {
      template_id,
      slot_id,
      classroom_id
    }
  ]
}
```

字段含义：

| 字段 | 含义 |
|---|---|
| `task_id` | 教学任务 ID |
| `template_set_id` | 该任务选择的周次模板集合 |
| `template_id` | 模板集中的具体模板 |
| `slot_id` | 星期与大节组合后的时间槽 |
| `classroom_id` | 教室 ID |

### 2.3 编码边界

本项目采用“模板集 + 时间槽 + 教室”的混合编码方式。

- 周次分布由模板集枚举器提前生成。
- GA 不直接修改单周周次，而是在模板集范围内选择排课模式。
- GA 主要优化 `template_set_id`、`slot_id` 和 `classroom_id`。
- 这样可以减少搜索空间，避免 GA 在过细粒度周次上盲目搜索。

## 3. Slot 编码

时间槽采用星期和大节组合编码：

```text
slot_id = (day_of_week - 1) × 5 + (period_index - 1)
```

示例：

| `slot_id` | 含义 |
|---:|---|
| 0 | 周一第 1 大节 |
| 1 | 周一第 2 大节 |
| 4 | 周一第 5 大节 |
| 5 | 周二第 1 大节 |
| 24 | 周五第 5 大节 |

可用时间槽由生成配置和教师硬不可排共同过滤，GA 不会从不可用时间槽中选择。

## 4. 约束建模

排课约束分为硬约束和软约束。

### 4.1 硬约束

硬约束必须满足，违反时应给予极高惩罚或直接修复。

| 硬约束 | 说明 |
|---|---|
| 教师冲突 | 同一教师同一时间不能上多门课 |
| 班级冲突 | 同一班级同一时间不能上多门课 |
| 教室冲突 | 同一教室同一时间不能被多门课占用 |
| 教室容量 | 教室容量不能小于上课人数 |
| 教室类型 | 课程要求的教室类型需要匹配 |
| 时间范围 | 只能使用任务允许的周次、星期和节次 |
| 教师硬不可排 | 教师明确不可用时间不能安排课程 |
| 课时完整性 | 教学任务总课次必须被完整安排 |

### 4.2 软约束

软约束不一定绝对满足，但会影响方案质量。

| 软约束 | 说明 |
|---|---|
| 教师软避让 | 尽量避开教师不喜欢的时间 |
| 偏好星期 / 节次 | 尽量安排到教师偏好的星期或节次 |
| 避免早八 / 晚课 | 减少第一大节或最后一大节安排 |
| 紧凑排课 | 对偏好集中排课的教师减少分散安排 |
| 连续授课 | 避免教师连续上课过多 |
| 班级负载均衡 | 避免班级某一天课程过重 |
| 教室使用合理性 | 避免容量浪费过大或类型不匹配 |
| 周次分布均衡 | 避免课程过度集中在少数周 |

## 5. 适应度与选择机制（2026-05-29 重构）

本系统 GA 选择机制从"复合数值"重构为 **Deb (2000) 可行性优先** 双管道设计：

- **penalty_count(chromosome) → int**：只计数 H1-H6 硬约束违反数。0 = 可行，>0 = 不可行。
- **quality_score(chromosome) → [0, 1]**：L2 软约束 + L3 LightGBM 评分(α=0.6) + L5 LLM 干预(β=0.4)。

选择规则：
```
1. 可行解永远优于不可行解
2. 两个都可行 → 比 quality_score
3. 两个都不可行 → 比 penalty_count（选违反少的）
```

所有权重参数从 `generation_config` 读取，不再硬编码。详见 `docs/architecture/13-评分体系与约束分层设计.md`。

*参考: Deb, K. (2000). "An efficient constraint handling method for genetic algorithms."*

## 6. 初始种群生成


初始种群质量会影响 GA 收敛速度。

本项目可采用混合初始化策略：

| 初始化方式 | 说明 |
|---|---|
| 贪心初始化 | 优先安排候选少、冲突风险高的任务 |
| 模型排序初始化 | 优先选择模型质量分高的候选片段 |
| 随机初始化 | 保留一定随机性，增加种群多样性 |

推荐方式：

```text
先按任务约束紧张程度排序，再结合候选片段质量分构造初始解。
```

这样既能减少初始硬冲突，又能提高方案初始质量。

## 8. 遗传操作

### 8.1 选择

选择操作用于保留更优个体。

可采用：

- 锦标赛选择。
- 轮盘赌选择。
- 精英保留策略。

推荐保留少量最优个体，避免优质方案被随机操作破坏。

### 8.2 交叉

交叉操作在任务级进行，不拆散单个教学任务内部的模板结构。

```text
child_gene_i = parent_a_gene_i 或 parent_b_gene_i
```

这样可以避免交叉后破坏课时完整性。

### 8.3 变异

变异操作用于增加搜索空间。

可变异内容：

- 更换某个任务的时间槽。
- 更换某个任务的教室。
- 更换某个任务的模板集。

变异后必须重新检查硬约束，必要时进入 repair。

### 8.4 修复

repair 是本项目中非常重要的步骤，用于处理交叉或变异产生的硬冲突。

修复策略：

1. 找出冲突片段。
2. 枚举该教学任务的合法候选时间和教室。
3. 计算候选替换后的冲突减少量和质量分。
4. 优先选择能减少硬冲突且质量分较高的候选。

repair 的目标不是追求局部最优，而是尽快把不可行方案修复为可行方案。

## 9. GA 与模型的关系

模型不直接生成课表，只输出局部评分；GA 不学习偏好，只负责组合优化。

```text
模型：这个候选片段好不好？
GA：怎么把所有候选片段组合成一张整体最优课表？
```

这种分工有三个好处：

- 保留 GA 对组合优化问题的全局搜索能力。
- 利用模型学习真实课表和人工反馈中的隐性偏好。
- 避免让模型直接承担硬约束排课，降低错误风险。

## 10. 论文表述建议

可以在论文中这样表述：

```text
本文采用遗传算法对完整课表进行全局组合优化。染色体表示一张完整候选课表，基因表示单个教学任务的模板集、时间槽和教室选择。算法首先根据生成配置、教师画像和教室条件构造合法候选空间，再通过选择、交叉、变异和修复操作不断优化方案。适应度函数由硬约束惩罚、软约束惩罚、模板质量惩罚和模型局部评分共同组成，其中硬约束惩罚权重最高，以保证方案合法性；LightGBM 等模型输出的片段质量分则用于引导 GA 在合法空间内搜索更符合教师偏好和历史排课习惯的方案。
```

## 11. 答辩回答口径

如果老师问“GA 编码怎么设计”，可以回答：

```text
我没有让 GA 直接对每一周每一节课做完全随机搜索，而是先把周次分布抽象成模板集。染色体表示一张完整课表，基因表示一个教学任务的模板集、时间槽和教室选择。这样既能表达完整课表，又能减少搜索空间，避免 GA 过度随机。
```

如果老师问“适应度函数怎么设计”，可以回答：

```text
适应度函数由硬约束惩罚、软约束惩罚、模板分布惩罚和模型局部评分组成。硬约束权重最高，保证教师、班级、教室冲突优先被消除；软约束和教师画像影响方案质量；LightGBM 输出的片段评分用于引导 GA 搜索更符合历史偏好和人工反馈的候选组合。
```

如果老师问“模型和 GA 谁起主要作用”，可以回答：

```text
GA 负责完整课表的全局组合优化，模型只负责候选片段的局部质量评分。模型不替代 GA，也不覆盖硬约束，而是作为一个评分器帮助 GA 更快找到高质量方案。
```
