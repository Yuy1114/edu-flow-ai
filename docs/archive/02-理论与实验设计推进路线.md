# 理论与实验设计推进路线

> ⚠️ **V3 更新 (2026-06-02)**: 本文档的技术路线基于 V2 的 GA + 片段评分器框架。V3 架构下理论实验需重新围绕 Placement Model + CP-SAT 设计。部分方法论（如消融实验设计原则）可迁移。详见 [17-V3-CP-SAT排课架构设计](../architecture/17-V3-CP-SAT排课架构设计.md)。
>

后续重点不再是继续增加功能，而是把项目整理成一套能够被论文和答辩解释清楚的方法体系：

```text
基础数据
  ↓
教师画像建模
  ↓
候选排课片段生成
  ↓
LightGBM 局部质量评分
  ↓
GA 全局组合优化
  ↓
冲突检测与方案输出
  ↓
人工调整与反馈沉淀
  ↓
训练样本构建与模型迭代
```

核心目标是回答四个问题：

1. GA 为什么适合做完整课表的全局搜索？
2. LightGBM 为什么适合做候选排课片段的局部评分？
3. 教师画像如何从自然语言偏好变成可计算特征？
4. 如何通过消融实验证明该组合方案有效？

## 总体推进顺序

### 1. 核心链路设计说明

目标：先形成一份面向论文和答辩的总纲，统一后续所有章节的叙述口径。

需要说明：

- 系统输入：教学任务、教师、班级、教室、时间片、教师画像、生成配置。
- 系统输出：一组满足硬约束并尽量满足软偏好的候选排课方案。
- GA 职责：在全局约束下搜索完整课表组合。
- LightGBM 职责：对 `任务 × 模板 × 时间 × 教室` 候选片段进行局部质量评分。
- 教师画像职责：提供硬不可排、软偏好、负载倾向、空间偏好等约束和特征。
- 人工反馈职责：把教务调整行为沉淀为后续训练样本。

建议产物：

```text
核心链路设计文档
核心链路图
答辩用一句话项目定位
```

推荐项目定位：

```text
本项目不是让大模型直接生成课表，而是利用教师画像构建个性化约束与偏好特征，通过 LightGBM 对候选排课片段进行局部质量评估，再由遗传算法完成全局约束优化，并通过人工反馈形成持续训练闭环。
```

### 2. GA 编码与适应度函数设计

目标：回答“GA 在本项目里到底优化什么”。

需要重点补齐：

- 染色体表示：一个染色体表示一张完整课表。
- 基因表示：一个基因表示一个教学任务的模板选择、时间片选择和教室选择。
- 编码边界：周次由模板集固定，GA 主要调整 `slot_id` 和 `classroom_id`。
- 硬约束：教师冲突、班级冲突、教室冲突、容量不匹配、不可用时间片。
- 软约束：教师偏好、连续授课、早晚课、课程分布均匀性、跨楼栋成本。
- 适应度函数：硬冲突高权重惩罚，模板质量和教师偏好低权重惩罚，LightGBM 分数作为局部质量信号。
- 修复机制：当交叉或变异产生冲突时，通过候选替换降低硬冲突。

建议产物：

```text
GA 编码设计说明
适应度函数公式
硬约束 / 软约束分类表
```

### 3. LightGBM 选型论证

目标：回答“为什么选 GBM / LightGBM，而不是随机森林或其他方法”。

论证思路：

- 排课片段评分属于结构化表格特征任务，特征包括教师、课程、时间、教室、历史反馈等。
- LightGBM 对表格数据友好，在小中型数据上训练效率高，推理成本低。
- Boosting 逐步拟合残差，更适合学习“哪些候选容易被接受或调整”的细粒度排序信号。
- 随机森林稳定但主要通过多棵树平均降低方差，对细粒度排序和难样本迭代拟合能力相对弱。
- 深度学习对样本量要求高，可解释性较弱，不适合作为当前阶段主模型。
- 纯规则可解释但不能持续学习人工调整中的隐性偏好。

需要强调：

```text
LightGBM 不替代 GA，也不判断硬约束是否合法。
它只为 GA 提供局部候选质量评分，帮助 GA 更快找到高质量组合。
```

建议产物：

```text
LightGBM 选型说明
LightGBM / RandomForest / 纯规则 / 深度学习对比表
```

### 4. 教师画像增强设计

目标：把教师画像从“简单偏好描述”升级为“可计算、可解释、可训练”的特征体系。

建议分层：

| 画像层级 | 内容 | 用途 |
|---|---|---|
| 基础画像 | 院系、职称、可授课程、周课时上限 | 过滤与基础特征 |
| 时间画像 | 不可用时间、避免早八、偏好上午/下午 | 硬过滤与软惩罚 |
| 负载画像 | 连续授课承受度、每日课时上限、周内分布偏好 | GA penalty 与模型特征 |
| 空间画像 | 偏好教室类型、避免跨校区、固定楼栋偏好 | 教室候选评分 |
| 行为画像 | 历史调课次数、常见调整原因、满意度反馈 | 训练样本与模型特征 |

关键要求：

- 自然语言只是输入形式，不是最终画像事实。
- 最终画像必须落到结构化 JSON。
- 画像字段要同时进入 GA penalty 和 LightGBM 特征。
- 硬约束与软偏好必须严格区分，避免模型覆盖硬约束。

建议产物：

```text
教师画像特征设计表
画像字段到 GA penalty 的映射表
画像字段到 LightGBM 特征的映射表
```

### 5. 样本训练链路设计

目标：回答“训练样本从哪里来、经过哪些处理、如何形成可训练数据、模型如何迭代”。

这一部分属于完整的 train 链路，是后续做 LightGBM、RandomForest、XGBoost、纯规则对比实验的前置基础。训练链路未打通时，模型消融只能停留在理论对比；训练链路打通后，才能在同一批样本、同一组特征、同一套指标下公平比较不同模型。

#### 5.1 样本单位定义

建议把样本单位定义为：

```text
一个候选排课片段，而不是一整张课表。
```

一个样本可以表示为：

```text
sample = f(teaching_task, teacher, class_group, time_slot, classroom, current_schedule_context)
```

也就是判断“某个教学任务安排到某个时间和教室是否合适”。完整课表仍由 GA 组合优化完成，模型只学习局部候选质量。

#### 5.2 数据采集

需要采集四类数据：

| 数据类型 | 来源 | 作用 |
|---|---|---|
| 基础业务数据 | teaching_task、teacher、class_group、classroom、time_slot | 构造候选片段的基础特征 |
| 教师画像数据 | 教师自然语言偏好、结构化画像 JSON、画像快照 | 构造教师偏好与约束特征 |
| 真实课表数据 | 学校提供的历史课表、已执行课表、人工确认课表 | 作为高可信正样本来源 |
| AI 生成满意课表 | 基于同一批教学任务和约束，由 AI / 系统生成并经人工筛选认可的课表 | 作为扩充正样本和弱监督样本 |
| 系统排课结果数据 | 系统生成方案、最终确认方案、历史课表 | 构造正样本和方案上下文 |
| 反馈行为数据 | 人工调整、冲突检测、好坏标注、驳回原因 | 构造负样本、强反馈和样本权重 |

这里要明确区分三类样本来源：

| 样本来源 | 可信度 | 训练用途 |
|---|---|---|
| 学校真实课表 | 高 | 主训练正样本，用来学习真实排课习惯 |
| 人工认可的 AI 生成课表 | 中高 | 扩充正样本，补足真实数据不足的问题 |
| 规则生成 `sample.csv` | 低到中 | 冷启动或预训练样本，不能作为主要训练依据 |

当前已有的 `sample.csv` 更接近规则构造的冷启动数据，只能帮助模型学习容量、时间段、基础冲突等显式规则，不能代表学校真实排课偏好。真正有效的训练样本应来自“真实课表”和“被人工认为满意的生成课表”。

采集阶段的关键不是直接训练，而是先把课表转成统一的片段样本。每一条课表记录都要能还原为：

```text
课程 / 教学任务 + 教师 + 班级 + 时间片 + 教室 + 周次 + 是否被认可
```

尤其要记录：

- 学校真实课表中每一节课的教师、班级、时间、教室、周次。
- AI 生成了哪些候选课表。
- 哪些 AI 生成课表被人工认为“满意”。
- 不满意的生成课表为什么被拒绝。
- 教务最终选了哪套方案。
- 哪些片段被移动、替换或删除。
- 调整前是什么，调整后是什么。
- 调整原因是冲突、偏好不满足，还是人工主观选择。
- 教师画像在当次排课时的快照是什么。

#### 5.3 数据清洗

采集后的原始数据不能直接训练，需要先清洗。

建议清洗规则：

| 清洗项 | 处理方式 |
|---|---|
| 缺失教师、教室、时间片 | 删除样本或标记为不可训练 |
| 真实课表字段格式不统一 | 统一教师、班级、教室、星期、节次、周次编码 |
| 同一课程跨多周重复记录 | 展开为片段样本，或按模板聚合后再生成片段 |
| 教师 / 教室 / 班级名称不一致 | 建立名称映射表，统一到系统内部 ID |
| AI 生成课表未经过人工筛选 | 不作为正样本，只能作为候选或待标注数据 |
| 教室容量小于班级人数 | 作为硬非法候选，不进入正样本 |
| 教师 hard_unavailable 命中 | 作为硬非法候选，不让模型学习成可接受候选 |
| 重复调整记录 | 按时间窗口合并，避免同一行为重复计数 |
| 调整后又调回原位 | 做相消处理，不作为强负反馈 |
| 测试数据和真实数据混杂 | 加 `data_source` 字段区分，训练时可降权或剔除 |
| 异常 label | 保留原始事件，但不进入训练集 |

这里要特别说明：硬约束非法的数据不应该简单交给模型“自己学”，因为硬约束必须由规则和 GA 精确保证。模型训练主要学习软偏好和局部质量排序。

#### 5.4 数据筛选

清洗后还需要筛选，保证训练数据质量。

建议筛选标准：

- 只保留字段完整、能映射到真实教师 / 教室 / 时间片的样本。
- 优先保留真实确认、真实调整、人工标注样本。
- 对纯规则生成的冷启动样本降权处理。
- 剔除明显违反硬约束但被误标为正样本的数据。
- 控制同一教师、同一课程、同一班级的样本占比，避免模型过度记住少数对象。
- 检查正负样本比例，避免全部都是正样本或全部都是负样本。

筛选后的数据可以分为四层：

| 数据层级 | 用途 |
|---|---|
| real timetable samples | 学校真实课表转出的高可信训练样本 |
| accepted AI timetable samples | 人工认可的 AI 生成课表转出的扩充样本 |
| cold-start samples | 没有真实反馈时，用规则生成的初始训练样本 |
| feedback samples | 教务确认、调整、冲突检测产生的真实反馈样本 |
| evaluation samples | 固定验证集，用来比较不同模型效果 |

#### 5.5 特征处理

建议特征分为六组：

| 特征组 | 示例 |
|---|---|
| 教学任务特征 | 课程类型、总学时、班级人数、合班数量、所需教室类型 |
| 教师特征 | 院系、职称、周课时上限、历史调课次数 |
| 时间特征 | 星期、节次、是否早八、是否下午、是否晚课 |
| 教室特征 | 容量、类型、楼栋、容量冗余、是否类型匹配 |
| 画像特征 | 是否命中偏好日、是否命中避让时段、紧凑排课偏好、最大日负载 |
| 上下文特征 | 教师当日负载、班级当日负载、教室当日负载、当前方案冲突风险 |

处理方式：

- 类别特征：课程类型、教室类型、院系、职称等可以做枚举编码或类别特征处理。
- 数值特征：人数、容量、课时、负载等保留数值并做必要归一化。
- 布尔特征：是否早八、是否命中画像避让、是否容量足够等转为 0/1。
- 上下文特征：必须在构造样本时基于当前方案状态计算，不能只看单个片段。

#### 5.6 标签与权重设计

标签设计：

| 样本来源 | label | sample_weight | 含义 |
|---|---:|---:|---|
| 学校真实课表片段 | 1.0 | 1.2 | 高可信正样本 |
| 人工认可的 AI 生成课表片段 | 1.0 | 0.8~1.0 | 扩充正样本 |
| 最终采纳片段 | 1.0 | 1.0 | 普通正样本 |
| 人工调整后的片段 | 1.0 | 1.4 | 强正样本 |
| AI 生成但人工不满意片段 | 0.0 | 0.8~1.2 | 负样本或待分析样本 |
| 人工调整前的片段 | 0.0 | 1.2 | 负样本 |
| 冲突片段 | 0.0 | 1.3 | 强负样本 |
| 明确差评片段 | 0.0 | 1.5 | 强负样本 |
| 规则冷启动正样本 | 0.6~1.0 | 0.3~0.5 | 弱监督样本 |
| 规则冷启动负样本 | 0.0~0.4 | 0.3~0.5 | 弱监督样本 |

如果论文里不想讲得太复杂，可以统一说：真实人工反馈权重大于规则生成样本，明确调整行为权重大于普通确认行为。

#### 5.7 数据集划分

建议按排课任务或学期划分，而不是随机打散所有片段。

推荐方式：

```text
训练集：历史任务 A/B/C
验证集：历史任务 D
测试集：历史任务 E 或最近一次真实排课任务
```

原因：如果随机按片段划分，同一个教师、同一门课、同一次排课任务的相似样本可能同时出现在训练集和测试集里，评估结果会偏乐观。

#### 5.8 模型训练

训练流程：

```text
原始事件数据
  ↓
数据清洗
  ↓
样本筛选
  ↓
特征构造
  ↓
标签与权重生成
  ↓
训练集 / 验证集 / 测试集划分
  ↓
训练 LightGBM / RandomForest / XGBoost 等模型
  ↓
离线评估
  ↓
发布效果最稳定的模型
```

LightGBM 在系统中输出的是候选片段质量分：

```text
score(task, teacher, slot, classroom, context) → 0.0 ~ 1.0
```

GA 使用该分数辅助初始化、候选排序、repair 和 fitness 计算，但硬约束仍由规则判断。

#### 5.9 评估指标

训练阶段可以使用两类指标。

模型指标：

| 指标 | 说明 |
|---|---|
| AUC | 区分好 / 坏候选的能力 |
| LogLoss | 概率预测质量 |
| Precision@K | 排名前 K 的候选中好候选比例 |
| NDCG@K | 候选排序质量 |

排课业务指标：

| 指标 | 说明 |
|---|---|
| 教师偏好满足率 | 排课结果满足画像偏好的比例 |
| 人工调整次数 | 教务需要手动修改的片段数量 |
| 硬约束冲突数 | 教师、班级、教室冲突数量 |
| 平均 fitness | GA 输出方案质量 |
| 生成耗时 | 方案生成效率 |
| 方案采纳率 | 教务最终接受方案的比例 |

论文里更建议突出业务指标，因为项目最终目标不是模型分数好看，而是排课结果更好。

#### 5.10 与消融实验的关系

训练链路打通后，消融实验可以共用同一批数据：

```text
同一训练集 + 同一验证集 + 同一特征 schema + 同一业务指标
```

然后只替换评分器：

- 无模型：只用规则 penalty。
- RandomForest：使用随机森林输出候选质量分。
- LightGBM：使用 LightGBM 输出候选质量分。
- LightGBM + 教师画像增强：加入更完整的画像特征。

这样老师问“为什么选 GBM”时，就不是只靠口头解释，而是可以说：在相同数据、相同特征、相同 GA 搜索框架下，LightGBM 的方案质量和偏好满足率更稳定。

建议产物：

```text
训练数据采集流程图
数据清洗与筛选规则表
特征 schema 表
标签与权重设计表
训练 / 验证 / 测试集划分说明
模型评估指标表
反馈训练闭环图
```

### 6. 消融实验设计

目标：证明主方案不是“堆技术”，而是每个模块都带来可观察收益。

建议实验组：

| 组别 | 方法 | 目的 |
|---|---|---|
| A | 规则 + GA | 基线方案 |
| B | GA + RandomForest | 对比传统集成模型 |
| C | GA + LightGBM | 验证主模型收益 |
| D | GA + LightGBM + 教师画像增强 | 验证完整方案收益 |

建议指标：

| 指标 | 说明 |
|---|---|
| 硬约束冲突数 | 教师、班级、教室冲突数量 |
| 教师偏好满足率 | 满足软偏好的比例 |
| 人工调整次数 | 教务需要手动修改的片段数量 |
| 平均 fitness | GA 最终方案质量 |
| 生成耗时 | 一次生成方案所需时间 |
| 方案采纳率 | 生成方案被教务接受的比例 |

实验结论不需要证明 LightGBM 在所有场景绝对最优，而是证明：

```text
在本项目的数据规模和结构化特征场景下，LightGBM 能在生成质量、教师偏好满足率和推理耗时之间取得更好的平衡。
```

建议产物：

```text
消融实验方案
实验指标定义
实验结果记录表模板
```

## 当前优先级

1. 核心链路设计说明。
2. GA 编码与适应度函数说明。
3. LightGBM 选型对比说明。
4. 教师画像特征设计表。
5. 样本训练链路设计。
6. 数据闭环与画像演进说明。
7. 消融实验方案。

完成这些材料后，再根据文档反推是否需要补少量代码或实验脚本。不要先写代码再找理由解释，应该先把研究逻辑定稳。
