# 核心链路论文版总设计

> 更新时间：2026-05-26
> 目标：从论文与答辩角度梳理 Edu-Flow-AI 的核心技术链路，将教师画像、样本训练、LightGBM 局部评分、GA 全局优化、人工反馈和消融实验串成一条完整主线。

## 1. 项目定位

本项目面向高校教务排课场景，目标不是让大模型直接生成完整课表，而是构建一套“规则约束 + 教师画像 + 机器学习评分 + 遗传算法优化 + 人工反馈训练”的智能排课链路。

核心定位可以概括为：

```text
利用教师画像构建个性化约束与偏好特征，通过 LightGBM 对候选排课片段进行局部质量评估，再由遗传算法完成全局约束优化，并通过人工反馈形成持续训练闭环。
```

系统分工：

| 模块 | 职责 |
|---|---|
| 基础规则 | 保证教师、班级、教室、容量、时间等硬约束合法 |
| 教师画像 | 提供硬不可排、软偏好、负载倾向等个性化信息 |
| LightGBM / 对照模型 | 学习候选排课片段的局部质量评分 |
| GA | 在合法候选空间中搜索完整课表方案 |
| 人工反馈 | 记录教务确认、调整和评价，沉淀训练样本 |
| 消融实验 | 验证模型评分器和教师画像增强是否有效 |

## 2. 总体核心链路

项目核心链路如下：

```text
基础业务数据
  ↓
教师画像建模
  ↓
真实课表 / AI 满意课表采集
  ↓
片段级训练样本构造
  ↓
LightGBM 候选片段评分
  ↓
GA 完整课表全局优化
  ↓
冲突检测与多方案输出
  ↓
人工确认 / 调整 / 标注
  ↓
反馈样本沉淀
  ↓
模型重训与消融实验验证
```

这条链路体现了三个核心思想：

1. **硬约束由规则和 GA 保证**，避免模型生成不可用课表。
2. **软偏好由教师画像和模型评分学习**，提升方案的人性化程度。
3. **人工反馈进入训练闭环**，让模型从真实调整行为中持续改进。

## 3. 输入与输出

### 3.1 系统输入

| 输入类型 | 内容 |
|---|---|
| 教学任务 | 课程、教师、班级、总学时、课程类型、所需教室类型 |
| 教师信息 | 教师 ID、院系、职称、可授课程、周课时上限 |
| 班级信息 | 班级 ID、人数、合班关系 |
| 教室信息 | 教室 ID、容量、类型、楼栋 |
| 时间片 | 周次、星期、节次、大节编码 |
| 教师画像 | 硬不可排、软避让、偏好星期、紧凑排课倾向 |
| 历史数据 | 学校真实课表、人工认可 AI 课表、教务调整记录 |

### 3.2 系统输出

| 输出类型 | 内容 |
|---|---|
| 候选课表方案 | 多套满足硬约束的排课方案 |
| 片段质量分 | 每个候选片段的局部评分 |
| 冲突检测结果 | 教师、班级、教室、容量等冲突信息 |
| 画像解释 | 某片段是否命中教师偏好或避让规则 |
| 反馈样本 | 人工确认、调整、好坏标注形成的训练数据 |

## 4. 教师画像建模

教师画像是本项目的重要创新点之一。它不是简单文本备注，而是要转化为结构化特征，并进入 GA penalty 和模型特征。

画像分层：

| 层级 | 内容 | 用途 |
|---|---|---|
| 基础画像 | 院系、职称、可授课程、周课时上限 | 基础特征 |
| 时间画像 | 不可用时间、避免早八、偏好上午/下午 | 硬过滤与软惩罚 |
| 负载画像 | 连续授课承受度、每日/每周课时上限 | GA penalty 与模型特征 |
| 空间画像 | 偏好楼栋、教室类型、跨楼栋成本 | 教室候选评分 |
| 行为画像 | 历史调课次数、常见调整原因、满意度 | 反馈训练特征 |

教师画像作用路径：

```text
教师自然语言需求
  ↓
结构化画像 JSON
  ↓
排课任务画像快照
  ↓
硬不可排过滤 + 软偏好 penalty + 模型特征
  ↓
GA 和 LightGBM 共同消费
```

关键原则：

- 自然语言只是输入体验。
- 结构化 JSON 才是排课事实。
- 硬约束和软偏好必须区分。
- 模型不能覆盖教师硬不可排。

## 5. 训练数据链路

模型训练链路是后续消融实验的基础。

本项目不再把规则生成的 `sample.csv` 作为主要训练数据，而是采用混合数据来源：

| 数据来源 | 可信度 | 用途 |
|---|---|---|
| 学校真实课表 | 高 | 主训练正样本 |
| 人工认可 AI 课表 | 中高 | 扩充正样本 |
| 人工调整记录 | 高 | 强正 / 强负样本 |
| 冲突检测结果 | 高 | 强负样本 |
| 规则生成 sample.csv | 低到中 | 冷启动弱监督样本 |

训练数据处理流程：

```text
真实课表 / AI 满意课表 / 反馈事件
  ↓
字段标准化与 ID 映射
  ↓
数据清洗与异常过滤
  ↓
片段级样本构造
  ↓
负样本生成
  ↓
特征构造
  ↓
标签与权重设计
  ↓
训练 / 验证 / 测试集划分
```

## 6. 样本单位设计

本项目采用“三层样本单位”设计。

| 层级 | 样本单位 | 用途 |
|---|---|---|
| 片段级 | 一条具体课程安排 | 主训练单位 |
| 调整对级 | 调整前片段 vs 调整后片段 | 学习人工相对偏好 |
| 方案级 | 一整张课表 | 最终业务评估 |

主训练单位定义为：

```text
sample = f(teaching_task, teacher, class_group, time_slot, classroom, context)
```

含义是：

```text
某个教学任务，由某位教师，给某些班级，在某个时间和教室上课，在当前课表上下文中是否合理。
```

这样设计的原因：

- 一张课表可以拆成多条片段样本，缓解数据不足。
- 片段特征是典型表格数据，适合 LightGBM / RandomForest。
- 模型输出可以直接作为 GA 的局部评分信号。
- 方案级数据样本少、维度高，不适合作为主训练单位。

## 7. LightGBM 局部评分

LightGBM 的职责是对候选片段进行局部质量评分：

```text
score(task, teacher, class_group, slot, room, context) → [0, 1]
```

选择 LightGBM 的原因：

| 原因 | 说明 |
|---|---|
| 适合表格数据 | 排课特征主要是结构化特征 |
| 适合小中型数据 | 当前真实课表和反馈样本有限 |
| 学习细粒度偏好 | boosting 能逐步拟合难样本 |
| 推理速度快 | 适合 GA 搜索中频繁调用 |
| 工程接入简单 | 可作为候选片段评分器接入现有链路 |

LightGBM 不负责：

- 判断硬约束是否合法。
- 直接生成完整课表。
- 覆盖教师硬不可排。
- 替代 GA 做组合优化。

LightGBM 负责：

- 学习真实课表和人工反馈中的偏好。
- 输出候选片段局部质量分。
- 引导 GA 更快找到高质量完整方案。

## 8. sigmoid 评分归一化

由于模型原始分、规则惩罚分、教师画像惩罚分可能处在不同尺度，需要统一映射到 `[0, 1]` 区间。

采用 sigmoid 函数：

```text
sigmoid(x) = 1 / (1 + e^(-x))
```

综合评分：

```text
raw_i = model_i - λ × penalty_i
q_i = sigmoid(raw_i / T)
```

其中：

| 符号 | 含义 |
|---|---|
| `model_i` | 模型原始评分 |
| `penalty_i` | 规则惩罚、画像惩罚、冲突风险惩罚 |
| `λ` | 惩罚权重 |
| `T` | 温度系数，避免分数过早饱和 |
| `q_i` | 归一化后的候选片段质量分 |

作用：

- 统一不同评分来源的尺度。
- 压缩极端值，避免单项评分主导 GA。
- 方便不同模型在消融实验中公平比较。
- 为 GA 提供稳定的局部质量信号。

## 9. GA 全局优化

GA 负责完整课表的全局组合优化。

染色体表示一张完整课表：

```text
Chromosome = [TaskGene_1, TaskGene_2, ..., TaskGene_n]
```

基因表示一个教学任务的排课安排：

```text
TaskGene = {
  task_id,
  template_set_id,
  assignments: [
    { template_id, slot_id, classroom_id }
  ]
}
```

GA 优化目标：

```text
在消除硬冲突的基础上，尽量满足教师画像偏好、班级负载均衡、教室匹配和模型局部质量评分。
```

适应度函数：

```text
Fitness = HardPenalty × W_h
        + SoftPenalty × W_s
        + TemplatePenalty × W_t
        - ModelQuality × W_m
```

其中硬约束权重最高，保证方案合法性优先。

遗传操作：

| 操作 | 作用 |
|---|---|
| 初始化 | 生成初始课表种群 |
| 选择 | 保留优质个体 |
| 交叉 | 组合不同父代方案 |
| 变异 | 扩大搜索空间 |
| repair | 修复交叉 / 变异后的硬冲突 |

## 10. 人工反馈闭环

人工反馈是模型持续改进的来源。

反馈类型：

| 反馈事件 | 样本含义 |
|---|---|
| 方案确认 | 方案片段作为正样本 |
| 片段移动 | 调整前为负样本，调整后为正样本 |
| 片段删除 | 原片段作为负样本 |
| 好 / 坏标注 | 直接形成标注样本 |
| 冲突检测失败 | 冲突片段作为强负样本 |

训练闭环：

```text
生成方案
  ↓
人工确认 / 调整 / 标注
  ↓
记录反馈事件
  ↓
构建训练样本
  ↓
模型重训
  ↓
下一次排课加载新模型
```

## 11. 消融实验验证

为了证明方案有效，需要设计消融实验。

核心实验组：

| 组别 | 方法 | 目的 |
|---|---|---|
| A | 规则 + GA | 基线方案 |
| B | GA + RandomForest | 对比传统集成模型 |
| C | GA + LightGBM | 验证主模型收益 |
| D | GA + LightGBM + 教师画像增强 | 验证教师画像贡献 |

可选实验组：

| 组别 | 方法 | 目的 |
|---|---|---|
| E | GA + XGBoost | 与 LightGBM 做 boosting 对比 |
| F | GA + LightGBM，无 sigmoid | 验证归一化作用 |
| G | GA + LightGBM，无上下文特征 | 验证上下文特征贡献 |

业务指标：

| 指标 | 趋势 |
|---|---|
| 硬约束冲突数 | 越低越好 |
| 教师偏好满足率 | 越高越好 |
| 人工调整次数 | 越低越好 |
| 平均 fitness | 越优越好 |
| 生成耗时 | 越低越好 |
| 方案采纳率 | 越高越好 |

实验要证明的不是 LightGBM 永远最强，而是在当前结构化排课数据和教师画像场景下，LightGBM 能在方案质量、偏好满足率和生成效率之间取得更好的平衡。

## 12. 创新点总结

本项目创新点可以概括为三类。

### 12.1 教师画像驱动的个性化排课

教师画像不只是文本说明，而是被结构化为硬约束、软偏好和模型特征，参与候选过滤、GA penalty 和 LightGBM 评分。

### 12.2 LightGBM + GA 的分层优化架构

LightGBM 学习局部片段质量，GA 负责完整课表全局组合优化，实现“数据驱动评分 + 组合优化搜索”的分工。

### 12.3 基于真实课表与人工反馈的训练闭环

通过学校真实课表、人工认可 AI 课表和教务调整行为构建训练样本，让模型能够从真实排课偏好中持续学习。
