# GA 排课生成链路实现说明

> 更新时间：2026-05-31
> 范围：说明一次“生成方案”从 Java 发起到 Python 输出，再回到 Java 入库的具体实现路径。

## 入口概览

```text
前端点击生成
  ↓
AllocationSchemeGenerationService / Controller
  ↓
AllocationMlSchemeService.generateSchemes
  ↓
MlApiClient.generateSchemes
  ↓
Python FastAPI POST /api/ml/generate-scheme
  ↓
ml/scripts/generate_scheme_ga.py::run
  ↓
ml/scheduling/pipeline.py::generate_scheme
  ↓
schemes.jsonl
  ↓
Java parseGeneratedSchemes
  ↓
allocation_scheme / allocation_item
```

核心文件：

| 文件 | 职责 |
|------|------|
| `server/src/main/java/com/yuy/eduflow/allocation/AllocationMlSchemeService.java` | 调用 ML、跑评估、解析 `schemes.jsonl` |
| `server/src/main/java/com/yuy/eduflow/ml/MlApiClient.java` | 提交 FastAPI 任务并监听 SSE |
| `ml/api/routers/ga.py` | Python 任务提交、后台线程、SSE 状态推送 |
| `ml/scripts/generate_scheme_ga.py` | 从 DB 拉数据，循环生成多套方案，写输出目录 |
| `ml/scheduling/pipeline.py` | DB 数据转 `AllocationTask`，调用 GA，展开 rows |
| `ml/scheduling/ga.py` | penalty_count、evolve（Deb 2000）、交叉、变异、repair、初始化 |
| `ml/scheduling/scoring.py` | quality_score [0,1] 管道（L2软约束 + L3模型α + L5 LLMβ） |
| `ml/scheduling/selection.py` | deb_tournament_select、elite_select（Deb 2000 可行性优先） |
| `ml/scheduling/domain/features.py` | 冷启动规则打分（score_sample、索引构建、拒绝原因） |
| `ml/scheduling/enumerator.py` | 模板集枚举 |

## Java 调用 Python

`AllocationMlSchemeService.runModelScript` 构造请求体：

```json
{
  "task_id": 14,
  "teacher_profiles_jsonl": "/abs/path/ml/data/profiles/snapshots/task_14_20260525123000123.teacher_profiles.jsonl"
}
```

然后调用：

```text
POST /api/ml/generate-scheme
GET  /api/ml/generate-scheme/{task_uid}/stream
```

`MlApiClient` 会一直读 SSE，直到收到：

```text
event: completed
data: {"output_dir": "...", "scheme_count": 3, "timings_ms": {}}
```

如果收到 `failed`，Java 会抛出业务异常。

## Python 生成逻辑

`generate_scheme_ga.py::run(task_id, teacher_profiles_jsonl)` 做这些事：

1. 读取 `allocation_task`，确认任务存在。
2. 读取任务绑定的 `teaching_task_id`。
3. 读取生成配置 `allocation_task_generation_config`。
4. 读取教学任务、教室、时间片。
5. 读取教师画像：
   - 有 `teacher_profiles_jsonl` 时，使用快照。
   - 没有快照时，回退读取 DB。
6. 按生成配置过滤 `time_slot`：
   - `allowed_weeks`
   - `allowed_weekdays`
   - `allowed_periods`
7. `build_scoring_config(raw_config)` 将 DB 权重字段映射为 scoring 管道参数。
8. 只保留本次排课任务绑定的教学任务。
9. 按 `scheme_count` 循环生成 N 套方案（每套：pipeline → GA(penalty_count + quality_score + Deb 2000)）。
10. 写入 `schemes.jsonl` 和 `ga_summary.json`。

输出目录形如：

```text
ml/data/generated/task_{taskId}_{timestamp}/
├── schemes.jsonl
└── ga_summary.json
```

## schemes.jsonl 格式

每行一个 JSON 对象，对应一套方案：

```jsonl
{"items": [{"teaching_task_id": 1001, "time_slot_id": 9001, "classroom_id": 301, "week_number": 1, "day_of_week": 1, "period_index": 1, "teacher_profile_penalty": 60, "teacher_profile_penalty_explanation": "周一第一节尽量不排"}]}
{"items": [...]}
```

注意：
- `time_slot_id` 必须来自 DB 真实 `time_slot.id`。
- Java 入库主要依赖 `teaching_task_id`、`time_slot_id`、`classroom_id`。
- 画像解释字段会进入 `AllocationParsedItem`，用于方案摘要或前端解释。

## 多方案与 SSE

多方案问题的关键是：Python 不能生成完第一套就发送 `completed`。

当前实现是：

```text
for index in range(scheme_count):
    generate_scheme(...)
    schemes.append(...)
    summaries.append(...)

write schemes.jsonl
write ga_summary.json
return {"output_dir": ..., "scheme_count": len(schemes)}
```

只有 `run()` 完整返回后，`ml/api/routers/ga.py` 才推送 `completed`。

---

## Java 解析入库

`AllocationMlSchemeService.parseGeneratedSchemes` 读取：

```text
{output_dir}/schemes.jsonl
```

然后逐个 scheme 解析：

```text
schemesData[i].items[j]
```

每个方案会成为一个 `AllocationParsedScheme`，后续写入多个 `allocation_scheme`。
