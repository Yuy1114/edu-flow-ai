# AI 生成课表人工筛选标准

> 更新时间：2026-05-26
> 目标：定义 AI / 系统生成课表进入训练样本前的人工筛选标准，确保“满意课表”可以作为训练数据扩充来源，而不是未经验证的伪样本。

## 1. 设计背景

在真实学校课表数量不足时，可以使用 AI 或当前排课系统基于同一批教学任务、教师、班级、教室和时间约束生成多套候选课表。候选课表经过人工筛选后，满意方案可以转为正样本，不满意方案或不满意片段可以转为负样本或待分析数据。

需要强调：

```text
AI 生成课表本身不等于训练样本。
只有经过人工筛选认可的 AI 课表，才能作为训练样本使用。
```

这样做的目的：

- 补足真实课表数量不足的问题。
- 增加训练样本多样性。
- 让模型不仅学习规则，还学习人工认为“合理”的排课偏好。
- 为后续 LightGBM、RandomForest、XGBoost 等模型消融实验提供更充分的数据。

## 2. 筛选对象

人工筛选的对象分为两个层级：

| 层级 | 对象 | 用途 |
|---|---|---|
| 方案级 | 一整张候选课表 | 判断整体是否可接受 |
| 片段级 | 某一条课程安排 | 判断局部安排是否合理 |

最终训练仍以片段级样本为主，但方案级评价可以提供整体质量标签。

## 3. AI 生成课表的前置条件

AI / 系统生成课表前，必须使用同一批基础约束：

| 约束类型 | 内容 |
|---|---|
| 教学任务 | 课程、教师、班级、总学时、所需教室类型 |
| 时间范围 | 可用周次、星期、节次 |
| 教室范围 | 可用教室、容量、类型、楼栋 |
| 教师画像 | 硬不可排、软偏好、负载偏好 |
| 硬约束规则 | 教师冲突、班级冲突、教室冲突、容量约束 |

如果不同候选课表使用的输入约束不一致，后续训练和消融实验就不公平。

## 4. 方案级筛选标准

一张 AI 生成课表是否满意，可以按以下维度评价。

| 维度 | 合格标准 | 说明 |
|---|---|---|
| 硬约束 | 无教师 / 班级 / 教室时间冲突 | 必须满足 |
| 完整性 | 所有教学任务均被安排完成 | 必须满足 |
| 教室匹配 | 容量足够，类型基本匹配 | 必须满足或少量可解释 |
| 时间合理性 | 课程分布不过度集中或离散 | 影响整体质量 |
| 教师偏好 | 尽量满足教师画像中的软偏好 | 影响满意度 |
| 班级负载 | 单日课程数量不过重 | 影响学生体验 |
| 生成可用性 | 教务不需要大量手动调整 | 影响方案采纳 |

建议方案级评分：

| 评分 | 含义 | 处理方式 |
|---:|---|---|
| 5 | 很满意，基本可直接使用 | 方案片段作为正样本 |
| 4 | 较满意，少量可接受问题 | 方案片段作为较高权重正样本 |
| 3 | 一般，需要一定调整 | 只保留满意片段，问题片段待分析 |
| 2 | 不满意，问题较多 | 不作为正样本，问题片段可作为负样本 |
| 1 | 不可用，严重冲突或明显不合理 | 作为负样本来源或剔除 |

## 5. 片段级筛选标准

片段级评价用于判断某一条课程安排是否适合转为训练样本。

| 维度 | 满意片段表现 | 不满意片段表现 |
|---|---|---|
| 时间 | 符合教师和班级可用时间 | 命中硬不可排或明显不合适时间 |
| 教室 | 容量足够、类型匹配 | 容量不足或类型明显不匹配 |
| 教师负载 | 不造成教师当天 / 本周过载 | 导致连续授课过多或周负载过高 |
| 班级负载 | 班级当天课程分布合理 | 班级一天课程过满或过于集中 |
| 画像偏好 | 满足或未明显违背教师偏好 | 明显违背软偏好 |
| 冲突风险 | 无教师 / 班级 / 教室冲突 | 存在硬冲突 |

片段级标签建议：

| 人工判断 | label | sample_weight | 说明 |
|---|---:|---:|---|
| 满意 | 1.0 | 0.8~1.0 | 可作为扩充正样本 |
| 一般但可接受 | 0.6~0.8 | 0.6~0.8 | 弱正样本 |
| 不满意 | 0.0~0.4 | 0.8~1.2 | 负样本或弱负样本 |
| 明显错误 / 冲突 | 0.0 | 1.3 | 强负样本 |

## 6. 人工筛选记录字段

为了让 AI 生成课表可追溯，筛选结果需要记录以下字段。

| 字段 | 示例 | 说明 |
|---|---|---|
| `generated_scheme_id` | `ai_scheme_001` | AI 生成方案 ID |
| `generation_config_id` | `config_20260526_01` | 生成配置 ID |
| `reviewer` | `教务老师A` | 筛选人 |
| `review_time` | `2026-05-26 16:30:00` | 筛选时间 |
| `scheme_score` | `4` | 方案级评分 |
| `scheme_accepted` | `true` | 是否整体认可 |
| `item_id` | `item_001` | 片段 ID |
| `item_label` | `1.0` | 片段标签 |
| `item_weight` | `0.9` | 片段权重 |
| `review_reason` | `时间合理，教室容量合适` | 人工原因 |
| `data_source` | `accepted_ai_timetable` | 数据来源 |

## 7. 不满意原因分类

为了后续分析和构造负样本，不满意原因需要尽量结构化。

| 原因类型 | 说明 |
|---|---|
| `teacher_conflict` | 教师同一时间多课 |
| `class_conflict` | 班级同一时间多课 |
| `room_conflict` | 教室同一时间多课 |
| `room_capacity_insufficient` | 教室容量不足 |
| `room_type_mismatch` | 教室类型不匹配 |
| `teacher_preference_violation` | 明显违背教师偏好 |
| `teacher_overload` | 教师当天或本周负载过高 |
| `class_overload` | 班级当天负载过高 |
| `bad_time_distribution` | 时间分布不合理 |
| `other` | 其他原因 |

这些原因后续可以转为：

- 负样本标签。
- 软惩罚特征。
- 教师画像改进依据。
- GA fitness 权重调优依据。

## 8. 样本转换规则

AI 生成课表经过人工筛选后，按以下规则进入训练数据：

| 筛选结果 | 转换方式 |
|---|---|
| 方案级 4~5 分，且无硬冲突 | 方案内片段转为正样本 |
| 方案级 3 分 | 只保留人工标记满意的片段 |
| 方案级 1~2 分 | 不整体进入训练集，只提取明确问题片段作为负样本 |
| 片段级满意 | `label = 1.0` |
| 片段级一般 | `label = 0.6~0.8` |
| 片段级不满意 | `label = 0.0~0.4` |
| 片段级硬冲突 | `label = 0.0`，较高权重 |

## 9. 与真实课表样本的关系

AI 生成满意课表不能替代学校真实课表，只能作为补充。

权重建议：

```text
人工明确调整反馈 > 学校真实课表 > 人工认可 AI 课表 > 规则生成 sample.csv
```

原因：

- 学校真实课表反映真实业务习惯。
- 人工认可 AI 课表反映当前任务下的可接受方案。
- 规则生成样本主要反映显式规则，不代表真实偏好。

## 10. 推荐执行流程

```text
准备同一批教学任务和约束
  ↓
AI / 系统生成多套候选课表
  ↓
自动检测硬冲突
  ↓
人工进行方案级评分
  ↓
人工标记关键满意 / 不满意片段
  ↓
记录筛选原因
  ↓
转为片段级训练样本
  ↓
合并真实课表样本
  ↓
训练模型并做消融实验
```

## 11. 最小可行筛选方案

如果时间有限，不必一开始做复杂标注系统，可以先采用最小方案：

1. 每批教学任务生成 5~10 套候选课表。
2. 人工给每套课表打 1~5 分。
3. 只把 4~5 分课表作为正样本。
4. 把 1~2 分课表中明显错误片段作为负样本。
5. 记录不满意原因。
6. 暂时不使用 3 分方案，避免标签模糊。

这样就能快速得到一批比规则 `sample.csv` 更有价值的训练数据。
