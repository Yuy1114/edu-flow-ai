# 数据闭环与画像演进设计

> ⚠️ **V3 更新 (2026-06-02)**: 本文档第 6 节"GA 自举数据生成"在 V3 架构下已不适用——V3 Placement Model 的训练数据直接从真实课表提取，不依赖 GA 自举冷启动。第 9-11 节（数据集划分、漂移监测、画像演进）的方法论仍有效。V3 的训练闭环详见 [17-V3-CP-SAT排课架构设计](./17-V3-CP-SAT排课架构设计.md)。
>

```text
以规则和 GA 保证排课方案的基本合法性，以教师画像、教室画像和历史反馈构造可计算特征，再通过 LightGBM 学习候选排课片段的局部质量评分，并将人工调整结果持续回流为训练样本。
```

因此，数据闭环的核心价值不是堆叠 AI 概念，而是回答三个问题：

1. 模型从哪里学习真实排课偏好？
2. 原始课表和反馈行为如何转成可训练样本？
3. 当教师、教室、课程和排课规则变化时，系统如何持续修正？

## 2. 数据来源分层

不同来源的数据可信度不同，不能混在一起直接训练。系统应按来源记录样本可信度，并在训练时设置不同权重。

| 数据来源 | 样本价值 | 可信度 | 建议用途 |
|---|---|---|---|
| 学校真实课表 | 反映学校真实排课习惯 | 高 | 主训练正样本 |
| 人工确认满意课表 | 反映系统方案被教务接受 | 高 | 正样本和方案级评估 |
| 人工调课记录 | 反映调整前后的偏好差异 | 极高 | 强正 / 强负样本、调整对样本 |
| 冲突检测结果 | 反映硬约束非法情况 | 极高 | 强负样本 |
| GA 高分方案 | 由规则和 fitness 生成 | 中 | 冷启动弱监督样本 |
| 规则生成候选片段 | 覆盖基础组合空间 | 低到中 | 冷启动、负样本补充 |
| LLM 解析结果 | 依赖自然语言理解质量 | 中低 | 需人工确认后进入画像或样本 |

关键原则：

- 真实课表和人工反馈优先级高于 GA 自举数据。
- 冲突检测产生的非法片段可以作为强负样本，但只能说明“不合法”，不能完整代表“不满意”。
- GA 自举样本适合冷启动，不能替代真实业务反馈。
- LLM 解析结果不能直接作为硬约束事实，必须经过结构化校验或人工确认。

## 3. 数据获取

数据获取阶段要围绕“排课片段”组织信息，而不是只保存完整课表截图或自然语言描述。

每条可训练记录至少应还原为：

```text
教学任务 + 教师 + 班级/合班组 + 时间片 + 教室 + 周次 + 当前上下文 + 结果标记
```

建议采集内容：

| 类型 | 采集字段 | 用途 |
|---|---|---|
| 基础业务数据 | 课程、教师、班级、人数、教室、时间片 | 构造候选排课空间 |
| 真实课表数据 | 已执行安排、周次、节次、教室、教师 | 构造高可信正样本 |
| 系统生成数据 | 候选方案、fitness、冲突数、评分明细 | 分析生成质量和构造弱样本 |
| 人工反馈数据 | 接受、拒绝、移动、替换、调整原因 | 构造强反馈样本 |
| 画像快照 | 当次排课时教师画像、教室画像版本 | 保证训练样本可追溯 |

需要特别记录“当时的画像快照”，而不是只读取最新画像。否则后续画像变化后，历史样本会失去可解释性。

## 4. 数据清洗

排课原始数据通常存在名称、时间、周次和合班格式不统一的问题，必须先做标准化。

| 清洗项 | 处理方式 |
|---|---|
| 教师名称不一致 | 建立教师名称到 `teacher_id` 的映射表 |
| 教室名称不一致 | 建立教室名称到 `classroom_id` 的映射表 |
| 时间格式不一致 | 统一转为 `slot_id`、星期、节次、大节编码 |
| 周次表达不一致 | 统一转为周次集合或 `week_pattern` |
| 合班信息复杂 | 统一生成 `class_group_id` 和学生总人数 |
| 缺失教师 / 时间 / 教室 | 标记为不可训练或进入异常队列 |
| 容量不匹配 | 作为硬非法候选或强负样本 |
| 重复课表记录 | 按教学任务、时间、教室、周次去重或聚合 |

清洗后的标准片段样本可以表示为：

```text
sample = f(task_id, teacher_id, class_group_id, slot_id, classroom_id, week_pattern, context)
```

## 5. 标签设计

标签设计决定模型到底学习什么。本项目中 LightGBM 不学习“生成完整课表”，而是学习：

```text
某个候选排课片段在当前上下文中是否合理、是否容易被人工接受。
```

### 5.1 单片段标签

| 标签 | 含义 | 来源示例 |
|---|---|---|
| `1.0` | 高质量正样本 | 真实课表、人工确认满意片段 |
| `0.8` | 弱正样本 | GA 高分方案中的合法片段 |
| `0.5` | 待确认样本 | 系统生成但未人工确认片段 |
| `0.2` | 弱负样本 | 低 fitness 方案中的低质量片段 |
| `0.0` | 强负样本 | 冲突片段、人工拒绝片段 |

### 5.2 调整对标签

人工调课记录可以构造更有价值的 pairwise 样本：

```text
调整前片段：label = 0
调整后片段：label = 1
```

这种样本能表达“为什么人工更喜欢调整后的安排”，比单纯正负样本更能反映隐性偏好。

### 5.3 样本权重

样本权重建议与来源可信度绑定：

| 来源 | 建议权重 |
|---|---|
| 人工调整后片段 | 高 |
| 人工拒绝片段 | 高 |
| 真实执行课表 | 高 |
| 人工确认满意方案 | 中高 |
| GA 高分方案 | 中 |
| 规则生成候选 | 低 |
| 未确认 LLM 解析结果 | 不直接训练 |

这样可以避免模型被大量自举样本“带偏”，确保真实人工反馈始终有更高话语权。

## 6. GA 自举数据生成

在真实课表和人工反馈不足时，可以使用 GA 和规则系统生成冷启动数据。

自举流程：

```text
基础业务数据
  ↓
规则生成候选片段
  ↓
GA 生成多套候选课表
  ↓
按 fitness、冲突数、偏好满足率筛选
  ↓
构造弱正样本、弱负样本和强负样本
```

可生成的样本类型：

| 类型 | 构造方式 | 用途 |
|---|---|---|
| 强负样本 | 人为制造教师、班级、教室、容量冲突 | 学习基础非法模式 |
| 弱正样本 | 高 fitness 且无硬冲突方案中的片段 | 模型冷启动 |
| 弱负样本 | 低 fitness 或软约束严重不满足片段 | 学习低质量模式 |
| 边界样本 | 合法但偏好满足较差的片段 | 提升排序区分能力 |

GA 自举的边界：

- 可以帮助模型学习显式规则和基础偏好。
- 不能替代真实课表和人工反馈。
- 不能证明模型已经掌握学校真实排课习惯。
- 应在论文中明确称为“冷启动弱监督数据”。

## 7. 特征工程

特征工程负责把教师、教室、课程、时间和上下文信息转成模型可消费的表格特征。

| 特征类型 | 示例 |
|---|---|
| 教师特征 | 院系、职称、周课时上限、历史调课次数 |
| 教室特征 | 容量、类型、楼栋、设备、历史投诉率 |
| 课程特征 | 课程类型、学时、是否实验课、是否专业课 |
| 班级特征 | 人数、年级、专业、合班数量 |
| 时间特征 | 星期、节次、是否早八、是否晚课、周次模式 |
| 画像命中特征 | 是否命中不可排、是否命中偏好、是否跨楼栋 |
| 上下文特征 | 教师当天课时、连续授课长度、班级当天课时 |
| GA 特征 | penalty、局部 fitness、所在方案冲突数 |
| 反馈特征 | 历史接受率、调整次数、常见调整原因 |

教师画像和教室画像不能只停留在文本展示层，必须映射为可计算特征。例如：

```json
{
  "avoidEarlyMorning": true,
  "preferCompactSchedule": true,
  "maxDailyHours": 4,
  "preferredBuildings": ["A", "B"]
}
```

可以转为：

```text
is_early_morning
hit_avoid_early_morning
daily_hours_after_assign
exceed_max_daily_hours
hit_preferred_building
```

## 8. 教室画像设计

除了教师画像，教室也可以被建模为画像对象。教室画像能让系统从“容量够不够”升级到“是否适合这门课”。

| 画像维度 | 示例 | 用途 |
|---|---|---|
| 基础属性 | 容量、楼栋、楼层、校区 | 容量过滤、空间成本计算 |
| 类型属性 | 普通教室、机房、实验室、阶梯教室 | 匹配课程类型 |
| 设备属性 | 投影、多媒体、实验设备、电脑数量 | 满足教学资源需求 |
| 空间属性 | 距离学院楼、跨校区成本 | 连续课空间惩罚 |
| 可用状态 | 临时停用、维修、考试占用 | 硬过滤 |
| 历史反馈 | 投诉率、调整率、常用课程类型 | 模型特征和软评分 |

教室画像示例：

```json
{
  "classroomId": "A301",
  "capacity": 80,
  "roomType": "multimedia",
  "building": "A",
  "preferredCourseTypes": ["lecture", "public_basic"],
  "unavailableSlots": ["MON_1_2"],
  "historicalAdjustmentRate": 0.08
}
```

## 9. 训练集、验证集、测试集划分

排课样本不适合完全随机切分，因为同一张课表拆出的片段高度相关，随机切分容易造成数据泄漏。

推荐优先级：

| 划分方式 | 说明 | 推荐程度 |
|---|---|---|
| 按学期划分 | 用历史学期训练，后续学期测试 | 高 |
| 按排课批次划分 | 同一批任务不跨集合 | 高 |
| 按方案划分 | 同一完整课表不同时进入训练和测试 | 中高 |
| 随机片段划分 | 容易泄漏上下文 | 低 |

如果真实数据不足，原型阶段可以采用：

```text
按排课任务批次或方案 ID 划分，避免同一方案中的片段同时出现在训练集和测试集。
```

三类集合职责：

| 数据集 | 用途 |
|---|---|
| 训练集 | 学习片段评分规律 |
| 验证集 | 调整模型参数、选择特征组合 |
| 测试集 | 最终评估泛化效果 |

## 10. 数据漂移监测

排课系统存在明显的数据漂移风险。教师、教室、课程、政策和教学计划变化后，历史规律可能失效。

| 漂移类型 | 示例 | 影响 |
|---|---|---|
| 教师漂移 | 新教师加入、教师偏好变化 | 教师画像和偏好特征失效 |
| 教室漂移 | 新楼启用、教室维修、设备变化 | 教室候选评分失效 |
| 课程漂移 | 新专业、新培养方案 | 课程类型和班级规模变化 |
| 规则漂移 | 学校调整排课政策 | 历史样本与新规则冲突 |
| 反馈漂移 | 人工拒绝率升高 | 模型评分与实际接受度偏离 |

可监测指标：

- 人工调整次数是否持续升高。
- 方案采纳率是否持续下降。
- 某类教师或教室的拒绝率是否异常升高。
- 时间片、楼栋、课程类型等特征分布是否明显变化。
- 模型高分片段是否频繁被人工拒绝。

触发策略：

```text
发现漂移
  ↓
检查规则和画像是否变化
  ↓
更新清洗映射和画像快照
  ↓
重新构造训练样本
  ↓
重新训练或回滚模型
```

## 11. 画像动态演进

画像动态演进的核心不是让系统随意修改事实，而是根据反馈逐步更新软偏好和行为统计。

| 画像内容 | 是否自动更新 | 说明 |
|---|---|---|
| 硬不可排 | 否 | 需要人工确认，不能由模型擅自修改 |
| 软偏好 | 可半自动更新 | 根据多次反馈形成倾向，建议人工确认 |
| 行为统计 | 可自动更新 | 调课次数、拒绝率、接受率等 |
| 画像权重 | 可训练更新 | 通过模型训练调整特征贡献 |
| 自然语言备注 | 不直接作为事实 | 需解析为结构化字段后使用 |

教师画像演进示例：

```text
多次观察：张老师周一早八课程被人工调走
  ↓
行为统计：early_morning_adjust_count 增加
  ↓
软偏好建议：avoidEarlyMorning = true
  ↓
人工确认后进入教师画像
  ↓
后续排课进入 GA penalty 和 LightGBM 特征
```

教室画像演进示例：

```text
多次观察：某机房被实验课频繁接受，被大班理论课频繁调整
  ↓
行为统计：实验课接受率高，大班课调整率高
  ↓
画像更新：preferredCourseTypes 增加实验课倾向
  ↓
后续候选教室评分发生变化
```

## 12. 论文与答辩口径

建议在论文中把能力分成两层：

| 层级 | 内容 | 当前定位 |
|---|---|---|
| 核心落地层 | 规则、GA、冲突检测、多方案输出、人工调课 | 必须真实可运行 |
| 智能增强层 | 教师画像、教室画像、LightGBM、反馈训练、漂移监测 | 原型实现 + 方法论设计 |

答辩时可以这样概括：

```text
本项目首先通过规则约束和遗传算法保证课表方案的可行性；在此基础上，将真实课表、人工调整、冲突检测和 GA 自举样本转化为片段级训练数据，通过教师画像和教室画像构造结构化特征，训练 LightGBM 对候选片段进行局部质量评分。系统不依赖模型判断硬约束，而是让模型学习软偏好和人工接受倾向，并通过反馈闭环支持后续画像演进和模型重训。
```

需要避免的说法：

- 不要说模型已经完全掌握学校真实排课规律。
- 不要说 LLM 可以直接可靠生成完整课表。
- 不要说画像可以无人工确认地自动修改硬约束。
- 不要把 GA 自举样本等同于真实业务样本。

更稳妥的说法：

```text
当前系统完成了核心排课生成链路和智能增强闭环的原型设计，真实生产环境还需要持续积累真实课表、人工反馈和运行监控数据，以提高模型评分和画像演进的可靠性。
```
