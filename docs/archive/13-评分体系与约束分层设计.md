# 评分体系与约束分层设计

> 更新时间：2026-05-29
> 目标：统一排课全流程（前置过滤 → 硬约束 → 软约束 → 模型评分 → LLM 干预）的评分/惩罚/过滤机制，消除各阶段权重量纲不一致、DB 参数未消费、LLM 约束无处挂载等问题。

---

## 一、分层总览

排课方案的评分不是单一函数，而是 **5 层流水线**，从上到下依次过滤/评分：

```
L0 · 前置过滤         Per-Assignment · GA 不可见
│  容量/类型/config/教师硬不可排
│  回答: 这个 (task, slot, room) 能不能进入候选？
│
├─ L1 · 硬约束         Runtime · 违反 → 方案不可行
│  H1-H6  教师/班级/教室冲突、任务缺失/重复、模板失效
│  回答: 这张课表能不能用？
│
├─ L2 · 软约束         Runtime · 可叠加权衡 · 规则定义
│  S1-S8  同天重复、早晚课、画像软避让、负载、容量浪费
│  回答: 在可用方案中，这张课表有什么已知的问题？
│
├─ L3 · 模型评分       Runtime · 数据驱动
│  LightGBM 局部评分 [0,1]
│  回答: 从历史反馈中，这个 (task, slot, room) 组合好不好？
│
├─ L4 · 模板质量       枚举阶段 · 独立量纲
│  T1-T5  段数/方差/覆盖/连续/中心偏移
│  回答: 周次分布的结构合理吗？
│
└─ L5 · LLM 干预       覆盖层 · 教务突发倾向
   L5-1~L5-3  时间段/教室/跨任务偏好
   回答: 教务当前有什么特殊要求？
```

## 二、各层详细定义

### L0 · 前置过滤（Per-Assignment）

**特征**：单条 `(task, slot, room)` 独立判定，不依赖全局排课状态。GA 完全感知不到被过滤掉的候选项。

| 编号 | 过滤条件 | 作用方式 |
|---|---|---|
| L0-1 | 学生数 > 教室容量 | 从 `candidate_room_ids` 剔除 |
| L0-2 | 课程要求教室类型 ≠ 实际类型 | 从 `candidate_room_ids` 剔除 |
| L0-3 | config: allowed_weeks / allowed_weekdays / allowed_periods | 从 `time_slots` 剔除 |
| L0-4 | 教师画像 hard_unavailable slot | 从 `candidate_slot_ids` 剔除 |
| L0-5 | 无候选 slot 或 无候选 room | 任务标记为不可行 |

实现位置：`ml/scheduling/pipeline.py` 的 `generate_scheme()` 中构建 `AllocationTask` 之前。

### L1 · 硬约束（Runtime）

**特征**：必须在完整方案上判定，违反 → 方案不可行。不存在"部分违反"的灰色地带。

| 编号 | 约束 | 判定条件 |
|---|---|---|
| H1 | 教师冲突 | 同一 (teacher_id, slot_id, week) 出现两次 |
| H2 | 班级冲突 | 同一 (class_group_id, slot_id, week) 出现两次 |
| H3 | 教室冲突 | 同一 (room_id, slot_id, week) 出现两次 |
| H4 | 任务缺失 | 方案中缺少某个教学任务 |
| H5 | 任务重复 | 同一 task_id 在染色体中出现两次 |
| H6 | 模板失效 | template_set_id 越界或 assignment 数不匹配 |

判定函数：`penalty_count(chromosome) → int`，返回违反的硬约束总数。返回 0 表示可行。

### L2 · 软约束（Runtime · 规则定义）

**特征**：人工定义的偏好规则，可叠加、可权衡、各项之间按权重比较。所有参数从 `generation_config` 读取，不再硬编码。

| 编号 | 软约束 | 判定条件 | config 字段 |
|---|---|---|---|
| S1 | 同天多时段 | 同一任务的多个 template 在同一天 | `same_day_weight` |
| S2 | 晚课 | period ≥ 4 | `late_period_penalty` |
| S3 | 教师画像软避让 | profile_penalty(teacher, slot) | `profile_penalty_scale` |
| S4 | 早八 | period == 1 | `early_period_penalty` |
| S5 | 教师日负载 | 教师当天已有课时数 | `teacher_day_load_penalty` |
| S6 | 班级日负载 | 班级当天已有课时数 | `class_day_load_penalty` |
| S7 | 教师周超限 | 教师周课时超 max_weekly_hours | `teacher_overload_penalty` |
| S8 | 容量浪费 | capacity_ratio < 0.6 | `capacity_waste_penalty` |

作用方式：在 `quality_score()` 中按配置权重累加扣分，输出归一化到 [0, 1]。

### L3 · 模型评分（Runtime · 数据驱动）

**特征**：LightGBM 学习出来的隐性偏好，不是人工定义的规则。模型输入 50+ 维特征，输出 [0, 1] 评分。

- 训练数据来源：
  - 冷启动：`score_sample()` 规则伪标签（`generate_training_samples.py`）
  - 增量：人工反馈事件 → `build_feedback_training_samples.py`
- 推理时：`AssignmentScorer.score(task, template, slot, room) → [0, 1]`
- 在 `quality_score()` 中的权重：`α`（默认 0.6）

### L4 · 模板质量（枚举阶段 · 独立量纲）

**特征**：评价周次分布结构，不涉及具体 slot/room 选择。只在枚举器内部排序用。

| 编号 | 指标 | 含义 | 默认权重 |
|---|---|---|---|
| T1 | 段数 | 模板数量 | `seg_penalty = 20 × n` |
| T2 | 方差 | 周次负载均匀度 | `var_penalty = 10 × variance` |
| T3 | 覆盖 | 可用周使用率 | `coverage_penalty = 100 × missing` |
| T4 | 连续 | 周间最大间隔 | `discontinuity = 30 × max(0, gap - 2)` |
| T5 | 中心 | 偏离学期中轴 | `balance_penalty = 2 × offset` |

### L5 · LLM 干预（覆盖层 · 教务突发倾向）

**特征**：教务通过自然语言描述临时偏好变化，LLM 翻译为结构化约束，与 L3 模型分并排加权。

约束类型：

| 编号 | 类型 | 作用对象 | 挂载点 |
|---|---|---|---|
| L5-1 | 时间段偏好 | 特定 slot | L5 lane（quality_score 的 llm_score 部分） |
| L5-2 | 教室类型偏好 | 特定 room_type | L5 lane |
| L5-3 | 跨任务关系 | 任务对 | L5 lane |

优先级 → 作用方式映射：

| priority | 作用方式 | 典型场景 |
|---|---|---|
| critical | 等同硬约束，进 penalty_count | "完全禁止" |
| strong | L5 lane 高权重扣分 | "非常不希望" |
| normal | L5 lane 中等扣分 | "尽量避开" |
| mild | L5 lane 轻微扣分 | "可以的话注意下" |

## 三、Penalty/Quality 双管道设计

### 3.1 理论基础

基于 Deb (2000) "An efficient constraint handling method for genetic algorithms" 提出的可行性优先原则：

> 1. 可行解永远优于不可行解
> 2. 两个都可行 → 比目标函数
> 3. 两个都不可行 → 比谁违反少

### 3.2 函数定义

```python
def penalty_count(chromosome) -> int:
    """返回硬约束 H1-H6 的违反总数。0 = 可行。"""
    count = 0
    count += teacher_conflicts
    count += class_conflicts
    count += room_conflicts
    count += missing_tasks
    count += duplicate_tasks
    count += invalid_templates
    return count


def quality_score(chromosome) -> float:
    """返回 [0, 1] 的综合质量评分。"""
    score = 1.0
    
    # L2: 规则软约束（权重从 generation_config 读取）
    score -= same_day_count      × cfg.same_day_weight      / scale
    score -= late_period_count   × cfg.late_period_penalty  / scale
    score -= early_period_count  × cfg.early_period_penalty / scale
    score -= profile_penalty_sum × cfg.profile_penalty_scale / scale
    # ...
    
    # L3: LightGBM 模型评分
    score += sum(ml_scores) / n_assignments × cfg.model_weight   # α
    
    # L5: LLM 干预评分
    score += sum(llm_scores) / n_assignments × cfg.llm_weight    # β
    
    return max(0.0, min(1.0, score))
```

### 3.3 锦标赛选择

```python
def tournament_select(population, k=4):
    candidates = random.sample(population, k)
    feasible = [c for c in candidates if penalty_count(c) == 0]
    
    if feasible:
        return max(feasible, key=quality_score)
    else:
        return min(candidates, key=penalty_count)
```

### 3.4 pipeline 中的不可行判定

即使所有个体都不可行（penalty_count > 0），GA 仍会返回违反最少的个体。pipeline 层做最终校验：

```python
if int(metrics.get("hard_conflicts") or 0) > 0:
    raise ValueError("排课失败：最终方案仍有硬冲突")
```

## 四、Config 参数设计

### 4.1 generation_config 表字段接入

| 字段 | 用途 | 默认值 |
|---|---|---|
| `allowed_weeks` | L0 周次过滤 | NULL（不过滤） |
| `allowed_weekdays` | L0 星期过滤 | NULL |
| `allowed_periods` | L0 节次过滤 | NULL |
| `scheme_count` | 生成方案数 | 1 |
| `profile_penalty_scale` | L2 S3 教师画像扣分系数 | 1.0 |
| `early_period_penalty` | L2 S4 早八惩罚 | 0（禁用） |
| `late_period_penalty` | L2 S2 晚课惩罚 | 0（禁用） |
| `same_day_weight` | L2 S1 同天重复惩罚 | 0.05 |
| `model_weight` (α) | L3 模型分在 quality_score 中的权重 | 0.6 |
| `llm_weight` (β) | L5 LLM 分在 quality_score 中的权重 | 0.4 |
| `llm_overrides` | LLM 约束 JSON 数组 | NULL |
| `capacity_waste_penalty` | L2 S8 容量浪费 | 0（禁用） |
| `teacher_overload_penalty` | L2 S7 教师周超限 | 0（禁用） |
| `teacher_day_load_penalty` | L2 S5 教师日负载 | 0（禁用） |
| `class_day_load_penalty` | L2 S6 班级日负载 | 0（禁用） |
| ~~`distribution_penalty_scale`~~ | ~~L4 分布不均匀惩罚~~ | ~~10.0~~ 已移除 |
| ~~`compact_bonus_weight`~~ | ~~L2 紧凑排课奖励~~ | ~~0（禁用）~~ 已移除 |

## 五、与旧方案对比

| 维度 | 旧方案 | 新方案 |
|---|---|---|
| fitness 定义 | 复合函数 (10M - penalty + ml_score) | 双管道: penalty_count (布尔) + quality_score ([0,1]) |
| 选择机制 | max(fitness) | 可行性优先 (Deb 2000) |
| 权重来源 | 硬编码常量 (HARD_CONFLICT_WEIGHT=1M...) | generation_config 全部可配 |
| LLM 约束 | 无处挂载 | L5 lane, 跟 L3 并排加权 |
| 惩罚/奖励 | 混在同一个数里 | 分流: penalty 管道只做加法, quality 管道只做 [0,1] |
| DB config 字段 | 11 个取了但没用 | 全部接入消费 |
| 模板枚举 | 权重硬编码 | 权重从 config 读（后续实现） |
| 训练标签 | score_sample() 硬编码 | 从 config 读取（后续实现） |
