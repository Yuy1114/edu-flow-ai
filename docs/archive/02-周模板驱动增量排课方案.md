# 周模板驱动的增量式排课方案（设计草案 v0.1）

> 2026-06-08

## 一句话核心

将排课问题从"18 周 × 全部课时"的高维组合优化，压缩为"一周模板 + 增量释放"的低维决策。

## 为什么

当前 CP-SAT 方案展开 18 周 × 439 任务 × 40 plan = **17560 个变量**，求解器反复判 INFEASIBLE。
而高校 95% 的课程本质上是**每周固定时段**——数据结构周二第 1-2 节就是整个学期都是周二第 1-2 节。展开 18 周做独立决策是冗余的。

## 核心思路

```text
不是：每个 (task, week, day, period) 独立决策 → 17560 变量
而是：每个 task 在周模板里只占一个 slot → ~975 变量
```

## 三层抽象

### 1. Pattern（课时模式）— 查表

基础单位：

```
1 个 slot（片段）= "周一第1节"这种 = 2 课时

理论课: 每次占 1 个 slot（2 课时）
上机课: 每次占 2 个连续 slot（一上午或一下午, 4 课时全包）
```

查表规则（理论课）：

| 课时 | freq/周 | weeks | 说明 |
|------|---------|-------|------|
| 4 | 1 | 2 | |
| 8 | 1 | 4 | |
| 16 | 1 | 8 | 或 freq=2, weeks=4 |
| 24 | 2 | 6 | 或 freq=1, weeks=12 |
| 32 | 2 | 8 | 每周 2 次, 8 周 |
| 48 | 3 | 8 | 每周 3 次, 8 周 |
| 64 | 4 | 8 | 每周 4 次, 8 周 |

查表规则（上机课, 每次 2 个连续 slot = 全上午/全下午 = 4 课时）：

| 课时 | freq/周 | weeks | 实际占位 |
|------|---------|-------|----------|
| 8 | 1 | 2 | 每周 1 个全上午/全下午, 2 周 |
| 16 | 1 | 4 | 每周 1 个全上午/全下午, 4 周 |
| 24 | 2 | 6 | 2 次放在同一个半天（全上午或全下午），每周 1 个半天, 6 周 |
| 32 | 2 | 4 | 每周 2 个全上午/全下午, 4 周 |
| 48 | 4 | 6 | 每周 2 个全上午/全下午, 6 周 |

Pattern 表示例：

```
24h 上机 → 每周 1 个全上午(2次连堂), 6 周
48h 上机 → 每周 2 个全上午/全下午(4次=2对), 6 周
```

所有 Pattern 的 weeks ≤ 16 ✅

示例：

```
数据库 32h 理论课 → freq=2, weeks=8 → 占周二1-2 + 周四1-2
Java上机 24h 上机课 → freq=2, weeks=6 → 占周三全上午（两个背靠背的 2h 次, 一共 4h）
```

### 2. Slot（周模板位置）— 决策单位

一周内的一个格子：

```
slot = (week_day, period_index)
```

5 天 × 5 节次 = 25 个 slot。每个 task 在模板里占 1 个 slot（理论课）或 2 个连续 slot（上机课 = 4 连堂）。

Slot 加上教室约束：

```
有效 slot = (week_day, period_index, room_type)

其中 room_type ∈ {普通教室, 机房}
```

### 3. WeekMask（有效周）— 不参与排课决策

WeekMask 是 Pattern 分配之后的**投影结果**，不参与排课的核心决策。

```
week_mask = {1, 2, 3, ..., duration_weeks}
```

例外周（停课、考试、节假日）直接在 mask 中排除。

## 排课流程

### 第一步：混合课程拆分

对于"理论 + 上机"混合的课程（如 24h 理论 + 8h 上机），拆成两个子任务：

```
原任务: 数据库原理（32h, 理论+上机）
→ 子任务 A: 数据库原理-理论（24h, 普通教室）
→ 子任务 B: 数据库原理-上机（8h, 机房）
```

### 第二步：按课时长度排序

从长到短：

```
64h (32周每周2次)  → 最先排
48h (24周每周2次)
32h (16周每周2次)
24h (12周每周1次)
16h (8周每周1次)
 8h (4周每周1次)
 4h (2周每周1次)  → 最后排
```

### 第三步：贪心 Slot 分配

对每个 task，从历史检索给出的候选 Slot 列表中依次尝试：

1. 选最高分的候选 slot
2. 检查该 slot 当前是否被占用（教师/班级/教室冲突）
3. 不冲突 → 占用
4. 冲突 → 尝试下一个候选

每个 (day, period) 维护教室类型计数器：

```python
slots_available = {
    (1,1): {"普通教室": 63, "机房": 38},  # 周一第1节
    (1,2): {"普通教室": 63, "机房": 38},  # 周一第2节
    ...
}
```

分配时递减，额度用尽则跳过。

### 第四步：动态释放

长课程排在前面，自然在学期中途结束。释放的 slot 被短课程填补：

```
Week 1-16: 数据库占周二1-2（机房A）
Week 17-18: 数据库结束 → 周二1-2 + 机房A 释放
→ 排入：Java实训（4h, 最后2周, 机房A恰好可用）
```

**贪心算法天然保证了释放顺序和利用效率**——不需要额外的调度逻辑。

### 第五步：CP-SAT 冲突消解（可选）

如果贪心算法在第一轮有冲突（大概率没有），用 CP-SAT 在 ~975 变量下消解——几秒内一定出解。

## 硬约束 vs 软约束的边界

排课阶段只处理硬约束：

```
硬约束: 同一教师/班级/教室在同一时段冲突 → 不允许
软约束: 教师偏好、个人倾向 → 不管，调课阶段处理
```

如果某个 slot 在教师的模式里是可行的（不存在硬冲突），就先排上去。教师不满意某个时段，**调课阶段手动或局部调整**，不影响方案生成。

## 特殊情况处理

### 上机课（4 连堂）

上机课占据 2 个连续 slot，全上午或全下午：

```python
class LabTask(Task):
    consecutive_slots = 2

# 上机课 16h → freq=1, weeks=4, 每次占 2 个连续 slot
# 分配时检查：
#   如果选 period=1 → 需要 1+2 都空闲（全上午）
#   如果选 period=3 → 需要 3+4 都空闲（全下午）
# 不允许跨上午/下午的组合（如 period=2+3）
```

### 实验课

归入上机课处理——2 个连续 slot，按上机课规则排。

### 停课/考试周

从 WeekMask 中排除即可，不影响 Slot 分配。

## 预期的方案质量

```
439 个 task（拆分为 ~500 个子任务）
Slot 分配: 贪心算法, < 1s
冲突消解: CP-SAT ~975 变量, < 5s（大概率不需要）
总耗时: < 10s
```
