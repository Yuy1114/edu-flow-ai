# 训练策略设计与讨论

> 日期：2026-06-10
> 状态：草稿，待 Yuy 复审

## 背景

V3.5 排课系统使用 LightGBM 单模型为每个教学任务预测 TopK 个 `(教室, day, period)` 资源组合。

训练数据来源：
- **全量数据**：每学期约 499 份班级课表，解析后得到约 12k–15k 条训练样本
- **反馈数据**：教务在审核台手动调课产生的记录（尚未接入训练管道）

## 核心问题

新的教学任务（新课、新教师、新班级）出现时，模型是否需要重训？
学期更替时的教室变动如何处理？增量续训是否可行？

## 模型泛化能力

LightGBM 多分类模型当前使用的特征：

| 特征 | 说明 | 跨学期稳定性 |
|---|---|---|
| `course_type` | 理论课 / 上机课 | 稳定 |
| `required_room_type` | 普通教室 / 机房 | 稳定 |
| `required_hours` | 总课时 | 稳定 |
| `student_count` | 班级人数 | 变化小 |
| `class_grade` | 年级（2022/2023/...） | 变化 |
| `course_name`（哈希） | 课程名 → 稳定编码 | 新课不可知 |
| `teacher_name`（哈希） | 教师名 → 稳定编码 | 新教师不可知 |
| `class_name`（哈希） | 班级名 → 稳定编码 | 新班级不可知 |


**新课、新教师、新班级的泛化**主要依赖语义特征（`course_type`、`required_hours` 等），不依赖名称哈希。模型会自动将特征相似的教学任务推荐到相近的时段和教室。

**标签空间固定性。** LightGBM 的输出是 `3953` 个固定类——对应所有已知的 `(教室, day, period)` 组合。如果训练集中从未出现过 `01107 周一第1节`，模型不可能预测它。

## 训练策略

### 学期更替 → 全量重训

```text
触发条件：新教室出现 / 教室列表变化
操作：train_from_history.py --raw-dir data/raw/schedules_新学期
耗时：约 2-3 分钟（499 份课表）
频率：每学期 1 次
```

### 学期内调优 → 增量续训

```text
触发条件：教务手动调课产生了反馈事件
操作：train_from_history.py --fine-tune --feedback-dir data/feedback/近期
      （不重新解析课表，只在现有模型上续训）
耗时：< 1 分钟
频率：按需，不多于每周 1 次
```

### 分界线

**标签空间（教室列表）发生变化 → 必须全量重训。**
**输入特征（新课/新教师/新班级）发生变化 → 模型可泛化，加训即可。**

## 未来可改进方向

### 1. 特征工程（短期，高价值）

当前课程名使用哈希编码，同类型课程之间的相似性无法传达。可增加：

```text
course_name → tf-idf / 词向量 → 低维稠密特征
teacher_name → 院系/职称 → 分类特征
```

让模型学到"数学类的课一般排上午"这类规律。

### 2. 目标函数（中期）

当前使用的是 3953 类多分类。如果未来出现以下需求，可考虑改为排序/打分模型：

```text
输入：(teaching_task, classroom, day, period)
输出：匹配分数
好处：新资源直接可打分，不需要重训
```

但当前阶段**不需要**做这个改动。

### 3. 教室变动检测（长期）

可增加一个脚本检测新教室的出现，自动触发全量重训：

```bash
python check_label_drift.py --model models/v3.5/placement_single --new-classrooms 01107
# 输出：WARNING: 发现 1 个新教室，建议全量重训
```

## 决策记录

| 决策 | 结论 |
|---|---|
| 模型框架 | LightGBM（不换 CatBoost） |
| 训练策略 | 每学期全量重训，学期内反馈加训 |
| 标签空间变化 | 必须全量重训（教室变动） |
| 特征空间变化 | 模型可泛化，不需要重训 |
| 增量续训实现 | 暂不实现，等反馈管道接入后再做 |
