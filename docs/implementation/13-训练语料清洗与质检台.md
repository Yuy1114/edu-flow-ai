## 解析修复：晚间子区间标注

晚间大节 `91011` 占三节，只用前两节的课会在格子里写出来：

```text
高166(9-10)
08203
```

`COURSE_CODE_PATTERN` 是双端锚定的，`高166(9-10)` 匹配不到任何东西，`_parse_timetable_cell`
返回空列表，整条 occurrence 就此消失——而且是静默的：该表的质量闸门给 100 分、判 accepted、
零警告。抽查 120 份历史课表发现 924 个这样的格子，**全部在晚间**。后果不是少几条样本，而是
训练集里几乎不存在晚间样本，"避开晚课"这条画像偏好根本无从学起。

修复分两半：

- 先用 `PERIOD_ANNOTATION_PATTERN` 剥掉标注再匹配，并把标注当作占用范围使用：占用落在第 9 节、
  跨 2 节，而不是整个三节大块。子区间必须落在本列大节内部才生效，否则以列头为准——一个写错的
  标注不能把课挪进别的大节。
- 解析为空的格子留痕：教学周行里解析不出内容的格子被计数并分流，`NON_TEACHING_MARKERS`
  （考试 / 国庆 / 报到注册 / 运动会…）是合法的非教学内容、不扣质量分，其余计入
  `unparsed_grid_cells` 并预警。

| 指标 | 修复前 | 修复后 |
|---|---|---|
| occurrences（全部文件） | 253,205 | 263,474 |
| 晚间 occurrence（全部文件） | 1,627 | 11,908 |
| 晚间 occurrence（`_combined`，accepted） | — | 11,288 |
| 晚间授课事件（合并后） | — | 6,783 |

## 可训练范围

范围内 = `理论课` + `上机课`；四类排除在范围外：课程类型不在引擎支持范围、课名命中集中实践
标记（课程设计 / 综合训练 / 实训 / 实习…）、整周块状占用、团队授课（3 人及以上）。6–7 次/周
是 `intensive` 档，交人工确认而非自动判定。

判定集中度用的是**每周次数**，不是占用节数。这门每周两次、每次连上 4 节的实验课，用节数去量
与"10 次/周铺满两周的课程设计"看不出差别；用次数就分得很开：常规课峰值 1–5、持续 10 周以上，
集中实践峰值 8–20、持续约 2 周。教师按 主讲 + 助教（≤2 人）保留，三人以上是教学团队，教师
偏好对一个组合没有意义。

**只标记，不丢弃**（与 `implementation/12` 的导入口径一致）：每条任务与每条 occurrence 都带
`trainable` + `untrainable_reason`，筛选发生在训练阶段，排除的样本离回归只差一个常量。

实测（`_scope`，班级级 12,221 行）：可训练 10,179；occurrence 200,254 / 248,538（80.6%）；
其中可训练晚间样本 9,032；节奏分档 regular 10,380 / intensive 706 / block 1,135；排除原因
整周块状占用 718、集中实践类课程 619、高频待人工确认 595、团队授课 110。

## 合班教学任务重建

学校一个班导出一份课表，一次合班授课会在参与的每个班的文件里各出现一次。把每份文件的每门课
当教学任务，就是 `CONTEXT.md` 明确要避免的"分班课表行"：同一次课被数 N 遍，容量、教师负载、
课时统计跟着错 N 倍。

还原分两遍：

1. **物理课次**，键 = (学期, 课程, 教室, 周, 星期, 节次)——一个教室在某一刻只能上一门课。班级与
   教师取并集，但**教师不进键**：285 处同一节课在不同班的课表里写着不同教师名，把教师放进键会
   把一次课拆成两次；分歧保留为 `teacher_name_conflict` 交人工。
2. **教学任务**，键 = (学期, 课程代码, 班级集合)。班级集合必须进键——`大学英语` 有多个平行班，
   同一课程代码下是互不相干的任务。判据是这个键下每个任务的教师集合都唯一，混键就会在一门课里
   混进不同教师。

合班因此是**结果而不是输入**：一个任务关联几个班，从时间-教室-课程的重合里推出来；原始数据里
没有合班标注。容量按班级人数求和（合班要装下所有人），缺人数时标 `student_count_complete=false`，
不猜。

实测：248,538 行 → 169,695 课次 → 8,833 任务；合班 3,613 个（40.9%），合班课次 69,964，最多
8 个班。可训练任务 7,037（授课 129,160 次 / 259,054 节，其中合班 3,310）；按任务口径的排除：
整周块状 629、集中实践 544、高频待人工 511、团队授课 112。分学期任务数
1,888 / 1,620 / 1,827 / 1,721 / 1,777。

## 质检台

载荷由 Python 聚合：重复出现的班级、教师、教室名走字符串下标表，周次压成 24 位掩码，
(任务, 星期, 节次, 教室, 跨度) 相同的落位折叠成一条。248,538 行变成 50,695 条落位、约 1.9MB
（compact JSON），本机实测构建 0.44s，按文件 mtime 缓存在进程内，命中缓存不重算。

六个视图（`DataQualityBoard.tsx` 的 `VIEWS`）：01 清洗总览、02 时段分布、03 班级课表、
04 教室占用、05 课程与任务、06 合班还原。筛选为学期 + 只看可训练。

两个视图**故意用不同算术**，因为问的问题不同：

- 时段分布只数**起始节次**——一次 4 节连上的实验课算一次课、不算四次，所以 2/4/6/8 节读数为空
  （实测授课起始节次只有 1/3/5/7/9，晚间 6,783 次，周末 9,709 次）。
- 教室占用把**续占节次**算进去——房间确实被占着。

前端 `src/lib/dataQuality.ts` 的列序常量（`T`/`P`）与 Python `_build_payload` 一一对应，改一边
必须改另一边。数据集缺失时接口返回 `status: "missing"` 并说明缺哪个文件、往哪挂载，而不是抛错。

## 快照表

`dataset_quality_snapshot`（迁移 016）为每次采集留一行：指纹、数据集目录、源文件数、occurrence
行数、课次数、任务数、去重行数、可训练任务/课次数、合班任务数、晚间课次数、完整报告 JSON、
采集人。`UNIQUE KEY (fingerprint)`。

指纹取自**清洗结果内容**而不是文件时间戳：两次清洗产出相同即同一指纹，所以重复采集不会堆积
无意义的行——`DataQualityService.capture` 查到同指纹就直接返回已有那条；而清洗口径真的变了，
一定会换指纹，前后两条快照就能指出具体动了什么。接口
`GET /api/ml/dataset/board`、`GET /api/ml/dataset/snapshots`、`POST /api/ml/dataset/snapshots`。

同一提交里删掉了 `app/api/v1/training.py`：十行的 `/health` 副本，从未在 v1 router 注册过。

## 自动验收

```bash
cd backend/python && python -m unittest discover -s tests -t .
```

三个文件共 40 项断言（`test_schedule_import_contract.py` 26、`test_teaching_task_reconstruction.py`
8、`test_training_scope.py` 6），本机全量 102 tests OK。覆盖：

- 晚间子区间：标注被剥离且保留、子区间收窄跨度、区间外回退列头、未标注格子仍占三节
- 考试与假日格子不算解析失败；未解释的格子被记录而不是丢弃
- 课次合并：同教室才合并、不同节次不合并、教师不进键但记分歧、合班带两个班的人数之和
- 缺人数标 `student_count_complete=false`；一个任务的课次按任务计一次而不是按班计
- 范围判定：每周一次理论课可训练、每周两次的实验课不被误判成集中实践、整周块状排除、
  课名排除、高频交人工、主讲+助教保留、团队授课排除、不支持的课程类型排除
