# 第一阶段模拟排课验收

> 范围：不读取真实教务数据，不依赖数据库，不启用 Placement Model。本验收证明“教学任务 → pattern → 绝对周排布 → 动态模板 → 冲突/课时终审 → 可查课表或显式待人工”的 rules-only 闭环。

## 统一业务语义

- 时间轴为每天 11 个 45 分钟原子小节：上午 1–4，下午 5–8，晚上 9–11。
- 自动排课只使用周一至周五的 1–8；晚间和周末保留给人工调课，不得用它们让均衡验收“虚假通过”。
- 理论课一次连续 2 节；上机/实验课一次连续 4 节。
- 一行数据代表一个教学任务。普通理论课中大多数任务直接关联同专业、同年级的两个相邻班；不再生成两条单班任务后猜测合并。
- 排课器按绝对周次占位，任务达到课时后立即释放后续周资源。排布完成后才将课表签名相同的周合并为动态模板，模板数不固定。

## 完整链路

1. `generate_synthetic_data` 按种子生成教学任务和带房型/座位的教室池。默认 `balanced` 为 1964 条任务、541 名教师、362 个班级和 320 间教室。
2. 生成后先执行资源分层必要容量预检：对每个房型，在每个座位分界上比对 18 周工作日白天的需求课时与可用课时。同时检查每条任务的固定/候选教室池是否存在合法教室。
3. `pattern_builder` 优先使用任务显式的每周次数和持续周数；否则用课时规则构造 pattern，并保留主讲/助教、所有班级、教师禁排、`allowed_weeks`、固定和候选教室。
4. `phase_scheduler` 在 `week × day × period` 上排布。它先过滤房型、容量和教室绑定，再校验所有教师、所有班级、教室、禁排、周次、连续节次和教师单日上限。
5. 初次贪心放置失败时执行有界局部重排。仍无合法位置的任务输出真实原因并进入 `needs_manual_review`，不伪造成功。
6. 对每条任务和全局执行最终课时守恒审计，并审计教师/班级/教室硬冲突、房型和容量。
7. 将每周实际活跃片段按签名去重为动态模板，每张模板携带显式 `week_numbers`。
8. 模拟实验台展示输入指纹、资源分层预检、pattern/任务追踪、动态模板、课时审计、失败解释及教师/班级/教室/课程组合查询。

## 场景契约

| 场景 | 用途 | 预期结果 |
|---|---|---|
| `balanced` | 第一阶段成功基线；常规普通教室 90 座，可容纳常见双班课 | 默认 1964 条在工作日 1–8 全部排完 |
| `formal-mix` | 在可行基线上抽样加入助教、禁排、限定周次、固定/候选教室 | 所有正式字段穿透 pattern 并在放置中真实生效 |
| `lab-heavy` | 提高上机课和机房占比 | 用于观察专用房型压力，不承诺全排 |
| `constrained` | 使用小教室、配对上机课和紧张资源 | 稳定进入 `needs_manual_review`，保留分层容量缺口和逐任务原因 |

## 自动验收门槛

- `balanced` 默认 1964 条任务在种子 `7`、`23`、`20260816` 下全部排完。
- 上述每轮必须同时满足：资源分层必要容量通过，未排数0，教师/班级/教室冲突0，容量违规0，逐任务和全局课时差0。
- 同一配置与种子在不同进程中必须得到相同输入指纹和 phase cover。
- `formal-mix` 回归必须证明助教、禁排、`allowed_weeks`、固定教室和候选教室都存在样本，且最终片段不违反任何这些约束。
- `constrained` 必须输出 `needs_manual_review`；不得把原因统一退化为 `not_placed`，也不得把待人工任务计为硬冲突。
- 参数变化后页面必须清除旧输入和结果；预览和运行必须复用同一份持久化模拟数据。
