# 课题研究的主要内容

本课题围绕高校排课的实际业务需求，结合约束建模、启发式算法与前后端系统开发，主要研究以下四方面内容。

## 一、多周教学任务与排课约束建模

以教学任务为基本排课单位，建立课程、主讲及协作教师、关联班级、教室、总课时、有效周次和连续节数之间的关系。采用“绝对周次—星期—原子小节”的时间坐标，完整表达合班教学、多教师参与和连续授课的资源占用。

硬约束包括教师、班级和教室时间互斥，教室容量与类型匹配，教师禁排，资源启用状态，任务有效周次及固定或候选教室范围等。连排课程检查完整占用区间，不得跨越规定的休息时段。独立审计教学任务覆盖情况与课时完成情况，显式报告未排任务和课时偏差。

软约束拟从课程周内分散程度、教师授课紧凑程度、班级日课时负荷和教室使用偏好等方面量化。明确各项惩罚的计算方式、归一化方法和权重范围，在满足硬约束的前提下评价与优化候选方案。

## 二、启发式自动排课与冲突检测

### 1. 约束驱动的启发式排课

将教学任务转换为包含每周次数、持续周数、连续节数和有效周集合的任务 Pattern。先执行资源必要容量预检，再根据专用资源需求、候选范围和教师及班级负荷等因素确定任务处理优先级。

通过合法候选枚举、贪心放置和有界局部重排生成候选课表。按照绝对周次维护占用，课程完成后释放后续周次资源，最终将安排相同的周压缩为动态周模板。无法完成的任务保留原始身份、缺失课时及失败原因，进入人工处理流程。

研究可配置的软约束候选评分，以及不同任务排序或候选选择策略下的多次求解。保存求解配置与结果，比较任务覆盖率、课时偏差、软约束评分和运行时间。

### 2. 冲突检测与验证

利用资源占用索引和周次位掩码等结构，检查全部教师、班级和教室的重叠占用，并校验容量、房型、有效周次和连续节次等条件。检测覆盖自动生成、草案修改及正式发布等环节。

通过人工标注与冲突注入测试，验证规定硬约束范围内的冲突检出率达到100%，同时检查合法样本的误报情况。使用实际教学数据验证100门课程、50间教室典型规模下排课计算时间不超过30秒，并同时报告排课完整性。

## 三、跨语言服务与数据批量处理

采用Spring Boot负责基础数据管理、业务流转、访问控制、审核发布和持久化，采用Python负责排课计算及课表数据解析，通过明确的HTTP契约协同运行。

正式排课由Java提交后台作业，Python执行求解，MySQL持久化任务配置、状态及结果，前端定时轮询进度。利用活动任务唯一约束防止同一排课任务重复提交，通过事务及发布锁保证确认操作的一致性。

完善教师、教室、班级和课程等基础数据的批量导入导出。利用Pandas等工具解析Excel及CSV，开展字段标准化、引用关系校验和异常分类；对冲突数据提供预览与人工确认，保留异常原因和导入批次记录，避免静默覆盖或丢弃。

## 四、可视化微调、复核发布与导出打印

基于React与TypeScript实现周历课表，支持教师、班级、教室、周次等组合查询，完整展示连续授课占用及不同周次的安排。

支持通过表单按精确周次新增、调整和删除授课片段，修改后重新执行硬约束与课时审计。拖拽及落点冲突提示作为交互增强方向，使用与表单修改一致的后端校验规则。

硬约束冲突不得人工豁免；未排任务、Pattern警告和课时偏差应显式展示，记录人工处理决定。方案确认前重新审计，并在事务中生成正式课表。提供教师、班级、教室和教务总表等Excel导出，以及适配课表布局的打印功能。
