# 拟解决的主要问题和最终目标

## 一、拟解决的主要问题

### 1. 实际教学任务的完整建模

解决固定周表或单教师、单班级模型难以表达合班、多教师、不同有效周次和连续授课的问题。通过统一原子时间坐标、明确任务关系及实际占用跨度，避免仅检查起始时间、遗漏关联资源或混淆课时与课次。

### 2. 复杂约束下的求解效率与排课完整性

在任务书允许的启发式规则路线下，研究资源预检、优先级排序、合法候选枚举和有界局部重排。兼顾运行时间与任务完成情况，避免以静默少排、放宽硬约束或遗漏授课周次的方式满足性能指标。

完善软约束评分和可配置权重，支持不同策略的多次求解，并提供统一的方案评价口径。

### 3. 冲突检测与课时偏差诊断

检查教师、班级和教室在重叠周次及完整连续区间内的占用，识别容量、房型、禁排和非法时间块等问题。通过冲突注入与合法样本测试验证检出率和误报情况，避免将“生成结果无冲突”直接等同于“检测器检出率100%”。

同时建立逐任务和全局课时审计，使未排任务、少排和多排课时均可追踪。

### 4. 长任务响应与发布一致性

通过后台作业、状态持久化和前端轮询解耦计算与页面请求；防止同一任务重复提交，并明确失败或中断后的状态。通过事务、行锁及发布锁协调草案修改与正式课表写入，避免并发操作绕过校验或产生不一致结果。

### 5. 自动排课与人工处理的衔接

提供可解释的未排原因和可视化课表，支持精确周次微调，修改后重新审计。硬约束问题必须修正，其他复核事项应显式记录处理原因，实现自动生成、人工修正和审核发布的衔接。

## 二、最终目标与交付内容

### 1. 可独立部署的Web系统

交付基于Spring Boot、Python/FastAPI、React和MySQL的前后端分离系统，提供明确的运行配置、数据库迁移和部署说明，并完善基本身份认证与访问控制。

### 2. 完整排课管理流程

实现教师、教室、班级、课程及教学任务管理，支持基础数据批量导入导出和异常反馈；实现自动排课、约束权重调整、多次求解与方案比较；提供教师、班级、教室等维度的课表查询、人工微调、审核发布、Excel导出与打印。

人工微调以表单编辑形成可验收闭环，拖拽及冲突高亮作为增强功能，不影响后端约束校验与发布规则。

### 3. 满足任务书指标并完成实际数据验证

使用实际教学数据，在100门课程、50间教室的典型规模下验证排课计算时间≤30秒。说明教学任务数、教师及班级数量、授课周次、课次、约束配置、测试硬件及计时边界，同时报告任务覆盖率、未排课时、硬冲突和课时偏差。

在规定硬约束测试范围内，通过已标注的冲突样本验证检出率达到100%，并报告误报情况。对满足资源条件的验收算例，以完整排课且无硬冲突为目标；对资源不足或搜索预算内未完成的情况，明确报告原因，不伪造成功结果。

### 4. 工程与论文成果

提交完整源代码、约束与算法设计说明、数据库设计及迁移文件、服务接口说明、部署文档、测试用例和实验报告。依据实际实现与可复现结果完成毕业论文，区分已经验证的结论、适用边界及后续改进方向。
